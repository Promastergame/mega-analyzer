# Игровая по картинкам

Тетрис и русские шашки теперь имеют видимое поле и управление в браузере.
ИИ получает **тот же PNG**, который показывается игроку. В запросе к решателю
нет готового массива клеток, фигуры, очереди или номера хода.

## Запуск

```powershell
go build -o .tmp/dai-visual-games.exe ./cmd/dai
.\.tmp\dai-visual-games.exe serve -light
```

Откройте `http://127.0.0.1:7480/games`. Страница доступна только у локального
сервера; токен подставляется автоматически. Одна запущенная игровая общая для
вкладок и MCP. «Новая партия» сбрасывает её; обновление страницы сохраняет партию.

- **Тетрис:** стрелки / кнопки, ↑ — поворот, пробел — сброс. Это пошаговый режим
  без таймера падения; фигура ждёт решения. Семь фигур перемешиваются мешками.
- **Шашки:** нажмите шашку и клетки её полного хода. По умолчанию человек играет
  белыми, ИИ отвечает чёрными. Снимите переключатель для игры вдвоём.
- **Ход ИИ:** один ход за текущую сторону. **Автоигра:** ИИ управляет обеими
  сторонами или последовательно укладывает фигуры. Пауза между ходами — 500 мс.
- «Глазами ИИ» показывает последний отправленный снимок. Время рядом — запрос
  от браузера до готового ответа, включая обработку изображения и передачу.

Русские шашки поддерживают обязательный бой, обратный бой простых шашек,
дальнобойных дамок, полные цепочки и превращение во время боя. Лимит демонстрации
300 полуходов; турнирные ничьи по истории не реализованы.

## Как проходит ход

Игровой движок рисует PNG → браузер показывает PNG → отправляет его в
`POST /v1/game` → распознаватель восстанавливает клетки → поиск выбирает ход →
`POST /v1/arena` проверяет действие по правилам и рисует новый кадр.

Движок игры и решатель разделены: `arena` не вызывает поиск ходов. Состояние
движка нужно для правил игры; API решателя его не получает. `source:"image"`
и `observed` в ответе показывают источник и результат распознавания.
При изменении поля с момента снимка применение хода отклоняется (HTTP 409).

## Границы зрения

Это компактное распознавание известного оформления, **не универсальная VLM**.
Нет OCR, распознавания произвольных сайтов, текстур или фотографий. PNG/JPEG/GIF
декодируются на CPU; GIF — первый кадр. Размеры ограничены прежними лимитами
1 MiB / 1 048 576 пикселей. Неизвестные цвета/знаки и неоднозначное поле дают ошибку.

Профиль `arena_tetris_v1`:

- `layout` задаёт область поля, `rows` (4–24) и `columns` (4–16).
- Фон `#182027`, закреплённые блоки `#85929d`, текущая фигура `#53dfce`.
- По четырём видимым активным клеткам определяются тип и положение фигуры.
  Если часть фигуры вне кадра, ход отклоняется. Очередь следующей фигуры не читается.
- Минимум 12 пикселей на клетку. Центры полых теней должны оставаться цветом фона.
- У симметричных I/S/Z одинаковые пиксели могут соответствовать двум поворотам
  SRS. Возвращается меньший номер подходящего поворота. Встроенная игра приводит
  начальную позу к этой же форме перед выполнением серии команд. Внешнему
  адаптеру нужна такая же договорённость; готовая серия не переносится вслепую.

Профиль `arena_checkers_v1`:

- Квадрат 8×8, минимум 24 пикселя на клетку. Светлая клетка `#e4dccb`, тёмная
  `#667466`; круглая белая шашка `#fff7e8`, чёрная `#252b32`.
- Золотой знак `#dba74a` в центре — дамка. Иное обозначение требует нового профиля.
- `layout.turn` — отдельный видимый индикатор стороны хода в том же изображении.
  Сторона не угадывается по расположению шашек и не берётся из JSON.
- `orientation` задаёт положение камеры: `white_bottom` (по умолчанию) или
  `black_bottom`. Это геометрическая настройка, а не скрытое состояние партии.

`see` / `/v1/see` автоматически узнают стандартные снимки игровой 240×480 и
384×416 при успешной проверке пикселей. Для изменённого размера/кадрирования
передайте `layout` с профилем. В `/v1/game` профиль передаётся явно.

## MCP с тем же видимым полем

```powershell
go build -o .tmp/arena-mcp.exe ./tools/arena-mcp
```

Задайте `DAI_API_TOKEN` перед запуском сервера и `dai play` в обоих терминалах
одинаково (или используйте токен, напечатанный сервером). Откройте `/games`, выберите
игру, затем во втором терминале:

```powershell
.\.tmp\dai-visual-games.exe play -input examples/games/play-tetris-images.json
# либо, после выбора шашек на странице:
.\.tmp\dai-visual-games.exe play -input examples/games/play-checkers-images.json
```

`arena-mcp` подключается к `http://127.0.0.1:7480`; для другого порта добавьте
`server.args:["-url","http://127.0.0.1:PORT"]`. `observe` возвращает только PNG,
`apply` выполняет проверенные команды по последнему наблюдению. После внешнего
сеанса обновите страницу, чтобы увидеть новое поле. Для живого просмотра без
внешнего MCP используйте «Автоигра» на странице.

`observation_mode:"image"` теперь режим MCP по умолчанию: JSON-текст и
`structuredContent` игнорируются, даже если скриншот отсутствует или испорчен.
Старые структурированные адаптеры должны явно указать
`observation_mode:"structured"`; пример лабиринта обновлён.

Повтор распознанного состояния останавливает MCP с `no_progress`, число ходов
ограничено `max_steps`. Ошибка распознавания, правил или устаревший снимок
останавливают действия; автоматического повтора не было и нет.

## Проверка и ресурсы

Тесты сверяют PNG → распознанное поле с независимым состоянием игры, выполняют
40 ходов каждой игры по изображениям, проверяют все повороты фигур, дамки,
обратную ориентацию, JPEG, масштабирование, кадрирование, человеческую цепочку
взятия, поддельный JSON рядом со скриншотом и отсутствие подмены при ошибке.

```powershell
go test -p 1 ./... -count=1
go vet ./...
python scripts/measure_game_budget.py --game tetris
python scripts/measure_game_budget.py --game russian_checkers
```

Скрипт измеряет именно **PNG → ход** по HTTP на позиции после восьми визуальных
ходов. Во время замера не запускайте тесты/автоплей. Память/CPU относятся только
к процессу DecisionAI, без браузера и отдельного MCP-процесса. Постоянная
перерисовка поля в этот цикл не входит. `-light` использует один Go worker и мягкий
лимит памяти 64 MiB; ОС не обеспечивает жёсткие 50 мс или мгновенный потолок 3% CPU.
При сильной нагрузке поиск может остановиться до первого законного хода — в таком
случае возвращается ошибка, а не произвольный ход.
