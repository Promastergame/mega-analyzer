# GNN в DecisionAI

Пакет `gnn/` — графовая нейросеть (R-GCN: типизированные рёбра, residual tanh-слои), без внешних библиотек.
Обратное распространение написано вручную и проверено численно (`gnn/gnn_test.go`). Вероятности откалиброваны температурой на отложенных данных.

## 1. Текст: события (`semai/events.go`)
Условие превращается в граф: слова → фразы-шаги → «история». Узел вопроса задаёт, о чём спрашивают («в коробке», «у Пети»).
Для каждого шага с числом GNN говорит: `plus` / `minus` / `none` / `init` (исходное количество).
Дальше сумма считается точно, а вероятность ответа — по распределению суммы (свёртка вероятностей шагов), а не «на глаз».

Обучение: `go run ./cmd/events-train` (синтетические истории: 24 места, 24 предмета, 16 героев, ~110 глаголов, эллипсис «ещё 5», «обратно», перекладывание, отвлекающие факты).
Каждый четвёртый глагол спрятан от обучения, чтобы проверить, как модель справляется с незнакомыми словами.

| тест (новые истории) | шаги верно | ответ верно |
|---|---|---|
| знакомые глаголы | 99.8% | 99.8% |
| незнакомые глаголы (спрятаны от обучения) | 91.5% | 92.5% |

## 2. Smali: роль константы (`smalirole/graph.go`)
Граф: константа ↔ её использования (с сигналами) ↔ инструкция после каждого использования ↔ окно ±2 инструкции.
Корпус: 100 APK, разбиение по приложениям (обучение 54 / калибровка 21 / тест 20 приложений, 20 083 констант в тесте),
та подсказка, по которой поставлена метка, скрыта (masked) — то есть это честная проверка обобщения.

| модель (test, masked) | accuracy | macro-F1 | ECE | точность при уверенности ≥80% |
|---|---|---|---|---|
| LR (было) | 0.860 | 0.825 | 0.012 | 0.960 |
| GNN | 0.875 | 0.851 | 0.008 | 0.966 |
| **LR + GNN (по умолчанию)** | **0.887** | **0.870** | 0.030 | **0.983** |

Переобучить: `go run ./cmd/smali-gnn -root <корпус apktool> -lr models/smalirole-model.json`.
`models/smalirole-gnn.json` подхватывается автоматически рядом с `smalirole-model.json`.

## v0.7 — честная проверка (`decision-ai eval`, страница `/eval`)

```
decision-ai eval -corpus <apktool-корпус> -out models/eval-report.json   # корпус не обязателен
decision-ai serve   →   http://127.0.0.1:7475/eval
```

Каждая модель оценивается не только по точности, но и по **честности уверенности** (ECE, Brier, NLL,
диаграмма надёжности) и по **доле решений без человека** при заданном риске (selective accuracy,
coverage@95/99, AURC). Пакет `evalkit` — общий для всех моделей.

**Ручные истории** (не синтетика): `semai/testdata/events-human.jsonl` — dev (40, по нему чинились),
`events-human-test.jsonl` — закрытый тест (30, при настройке не смотрели).

| | v0.6 | v0.7 |
|---|---|---|
| dev, точность | 26/40 | 40/40 |
| **закрытый тест, точность** | **15/30** | **28/30** |
| закрытый тест, ошибок при уверенности ≥90% | 10 | 0 |
| закрытый тест, ECE / Brier | 0.49 / 0.47 | 0.07 / 0.05 |

Что изменилось:
- числа-длительности («через 10 минут») не считаются количеством; «купил 6 яиц и положил **их**» — местоимение несёт число;
- генератор: безличные «привезли/увезли», «3 ученика ушли / зашли 8», «съел/продал/потратил» без места (из единственного места истории), передачи между людьми («Оля вернула ей 1»), «завяли и их выбросили», вопросы «осталось/сейчас/денег»;
- **осторожность к незнакомым словам**: модель хранит словарь обучения; слово, которого она не видела, смягчает уверенность шага (T = 1 + 2.5·k). Ответ выбирается по исходным вероятностям, уверенность — по смягчённым. На синтетике с незнакомыми глаголами: ECE ответов 0.075 → 0.018 при той же точности;
- **обучение с учётом калибровки**: к cross-entropy добавлен Brier-терм (`events-train -brier 1`). На незнакомых глаголах: ECE 0.083 → 0.080, coverage@95 76.5% → 79.1% — эффект небольшой, но в плюс; поставляемая модель обучена так;
- поставляемая модель обучена на всех глаголах (`-allverbs`); честные цифры обобщения на новые глаголы — в карточках «experiment» на `/eval`.

## v0.7.1 — истории без знаков препинания и несколько мест

- «в копилке было 50 рублей петя положил 20 рублей вынул 15 …» — длинная фраза без запятых режется на шаги по числам;
  «… 8 яблок | в вазе было 5» — место перед «было/лежало» относится к следующему шагу; «… съела их | через час мама …» — разрез перед «через N минут/час».
- В ответе считаются **все места истории**: «в коробке 8 → 9», рядом «в вазе 5 → 3» (`total.others`).
- Генератор: «взяла 2 яблока из вазы» (число перед местом), «положила 4 яблока в коробку» при вопросе про вазу → не влияет,
  «взяла 2 из вазы **и съела их**» → для мест уже ничего не меняет, «2 стула унесли на кухню» → минус для комнаты, «через час».
- **Ансамбль**: `semai/eventgnn.json` + `eventgnn-e*.json` (три GNN, сиды 2/3/4), вероятности усредняются.
  Один сид гуляет на ±2 ответа закрытого теста; ансамбль — 28/30, обе ошибки с уверенностью < 0.5, ошибок при ≥90% — 0.
  Честно: конструкция «унесли на кухню» добавлена после того, как закрытый тест на ней ошибся, — для неё тест уже не полностью закрытый.
