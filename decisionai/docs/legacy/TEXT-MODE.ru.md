# DecisionAI Text v0.3 — накопительная версия

Этот исходный модуль содержит всю версию v0.1 и текстовый режим v0.3 (совместим с моделями v0.2). Он добавляется к **исходному Mega-Analyzer.zip**, без предварительного применения v0.1. Патч добавляет файлы, не меняет ядро, go.mod или исходники основного проекта. Это отдельный add-on; автоматического hook в главный pipeline нет.

## Сборка и запуск на Windows 10 x64

Нужны Git (чтобы применить .patch) и Go 1.22+ (чтобы собрать EXE). Node, Python, CUDA, облачный API, AVX2 не нужны. Сам .patch — текстовый, EXE в него не включён.

Из корня оригинального проекта, рядом с его go.mod:

```powershell
git apply --check --whitespace=nowarn C:\Downloads\DecisionAI-v1-v2-cumulative.patch
git apply --whitespace=nowarn C:\Downloads\DecisionAI-v1-v2-cumulative.patch
cd tools\decision-ai
.\BUILD-WINDOWS.cmd
.\OPEN-TEXT-DEMO.cmd
```

После старта: **http://127.0.0.1:7475/text**. Ctrl+C — остановка. Измени путь Downloads на фактическое расположение патча. Не применяй поверх уже добавленного tools/decision-ai: используй свежую копию исходного архива. Если git apply --check сообщает ошибку, не применяй с --reject, сначала проверь версию/корень проекта.

`BUILD-WINDOWS.cmd` запускает тесты и vet, затем собирает `bin/decision-ai.exe` с CGO_ENABLED=0 и GOAMD64=v1. Компиляция проверялась для Windows x64; работа на физическом i5-3340 и Windows 10 не измерялась. Вся работа CPU-only, нет гигабайтных весов. После установки Go сборка не требует внешних Go-зависимостей: только stdlib.

Структурированный режим v0.1 остаётся на **http://127.0.0.1:7475/**; описание — README.ru.md.

## Поля как в Playground

- `state`: свободный текст о коде и контексте.
- `question`: текст вопроса.
- `true_when`: описание положительного класса.
- `false_when`: описание отрицательного класса.
- `threshold`: число 0..1, default 0.85.
- `task_id`: сейчас только `patch_effect_confirmation`.

Форма и JSON, загрузка/скачивание JSON, три демонстрационных сценария. Позитивный сценарий использует **вымышленные** records checks. Это не результат запусков настоящего приложения.

CLI:

```powershell
.\bin\decision-ai.exe text-analyze -input examples\text-request.json -text-model models\demo-text-model.json
.\bin\decision-ai.exe text-batch -input examples\text-cases.json -text-model models\demo-text-model.json
.\bin\decision-ai.exe text-train -input my-text-training.json -output models\my-text-model.json
.\bin\decision-ai.exe text-eval -input my-text-eval.json -text-model models\my-text-model.json -threshold 0.85
.\bin\decision-ai.exe serve -text-model models\demo-text-model.json
```

`-threshold` переопределяет порог запроса. Без `-text-model` используется явно обозначенная лексическая эвристика: не вероятность, ответ unknown, без модельного одобрения. `text-eval` проверяет отдельную размеченную выборку без дообучения: считает precision/recall/F1, Brier, log-loss, ROC AUC, ECE, operating points 0.5/0.7/0.85/0.9/0.95 и долю unknown; пересечение групп и текстов с обучением отвергается как leakage.

## Что за модель

v0.3: точный словарь без хеширования — слова, биграммы, триграммы внутри предложений и символьные 3–5-граммы по четырём полям (`word-char-tfidf-v2`), log-TF + IDF, поканальная взвешенная L2-нормализация, логистическая регрессия с балансом классов, сглаженная Platt-калибровка. Число признаков ограничено опцией (default 16384). Поверх — перекрёстные match-признаки: какие слова всего state всплывают во всём true_when / false_when (`state:w:match_true:<слово>`, `match_false:…`, плюс пороги перекрытия ge3/ge5). Локальные n-граммы видят только соседей, а match смотрит на поля целиком — линейный аналог cross-attention между посылкой и критерием, как в NLI. Оценка YES/NO, топ-12 точных слагаемых логита, энтропия, logit/intercept, покрытие и поддержка по полям, незнакомые слова, флаг усечения. Модели v0.2 (хеш 2048) и схемы v1 читаются для совместимости (match-признаки для них просто незнакомы, предсказания v1 бит-идентичны), но для новых признаков нужно переобучение.

Это **не LLM, не копия модели Playground, не универсальное понимание произвольных критериев**. Модель учится на примерах конкретной задачи и учитывает текст четырёх полей, но не исполняет критерии как логические правила. Изменение задачи/критериев требует подходящего корпуса и повторного обучения. Для точных логических условий используй структурированный режим v0.1.

Неизвестный текст: для каждого поля считается доля известных слов (coverage) и лексическая поддержка с половинным кредитом за знакомые подслова (support); итог — минимум по полям. Если support <0.6 или вход усечён до 2048 токенов — ответ unknown с `abstention_reasons` (`low_lexical_support`, `truncated_input`). Знакомые подслова сами по себе порог не проходят (максимум 0.5). Это простая OOD-эвристика, а не надёжный детектор всех новых смыслов. Известные слова в новом сочетании тоже могут быть вне распределения.

## Демо-модель и настоящая модель

`models/demo-text-model.json` v0.3 обучена на 624 синтетических шаблонных примерах (52 группы: 372 fit / 120 calibration / 132 test) и помечена `synthetic:true`. Корпус включает минимальные пары с отрицанием (тот же позитивный контекст, но с проваленным тестом → 0) и с чужим артефактом (тест прошёл, но на копии / не том файле / подпись не совпадает → 0). Без них модель уверенно отвечала YES даже на «тест НЕ прошел» и «тест на копии». Открытые перефразировки каверз модель всё равно может пропустить — это бесконечное поле, см. TEST-REPORT. Синтетическая модель выдаёт `synthetic_demo_estimate`; даже с хорошими records результат не становится одобрением production — только demo_only. На синтетике нельзя заявлять реальную точность; holdout Brier/accuracy относятся только к этому корпусу.

Собственные данные:

```powershell
.\bin\decision-ai.exe text-train -input my-text-training.json -output models\my-text-model.json
.\bin\decision-ai.exe serve -text-model models\my-text-model.json
```

Структура Dataset: `task_id`, `synthetic`, `samples`; каждый sample — `group`, `label` (0/1), `input`. Образец — examples/text-synthetic-training.json. `label=1`: подтверждений для положительного ответа достаточно; `label=0`: подтверждений недостаточно/есть отрицательные факты. Это не автоматическая метка «любой патч сработал».

Группы приложения/проекта делятся стратифицированно 60% fit / 20% calibration / 20% test с балансом классов. Словарь, отбор признаков (хи-квадрат, min_df, признаки минимум из 2 групп), IDF и оптимизация — **только на fit**; калибровка — на отдельных проектах. Нормализованные дубликаты внутри группы удаляются, across groups и конфликт меток отвергаются; превышение 2048 токенов в поле отвергает обучение (в инференсе — флаг truncated). Минимум 10 групп, 40 train, 20 calibration, 20 test и 5 примеров каждого класса в каждой части. Похожесть шаблонов/неправильные группы всё ещё могут создавать утечку: самостоятельно отделяй связанные приложения, повторные варианты и источники примеров. Минимумы — проверка формата, не рекомендация достаточного корпуса для реального качества. Опции: `max_features`, `epochs`, `learning_rate`, `l2`, `min_document_frequency`, `class_weight`.

В датасете должны быть минимальные пары: сборка успешна/ошибка; эффект получен/не получен; актуальный hash/устаревший; серверная зависимость/её отсутствие; неоднозначный текст; инструкции внутри файла. Флаг synthetic сообщает автор датасета: сам модуль не способен удостоверить происхождение обучающих данных. Не меняй флаг демо ради production-разрешения. Model JSON не подписан: загружай доверенные файлы.

## Почему высокий YES не разрешает всё

`candidate_code` — полный текст одного метода-кандидата. Вычисляется SHA-256 его **точных UTF-8 байтов**, с учётом line endings. Частичный Smali preflight не заменяет assembler/Dalvik verifier.

Отдельное `checks`:

```json
{
  "app_owned": true,
  "library": false,
  "scope": "test_fixture",
  "build": "pass",
  "runtime": "pass",
  "effect_verified": true,
  "server_dependency": "local_only",
  "tested_sha256": "64 hex characters for the current candidate"
}
```

Для gate должны совпасть принадлежность/scope, pass сборки, pass runtime и подтверждённый эффект, local_only и hash. Если не совпадают, **blocked при любом проценте модели**. Комментарий в state не может переопределить checks, потому что они не извлекаются из свободного текста. Это не делает сам текстовый классификатор полностью устойчивым к prompt injection; защищается независимая цепочка принятия решения.

Критически важно: **checks — записи, переданные вызывающим кодом, а не выполненные и удостоверенные этим модулем тесты.** Их надо получать из доверенного сборщика/раннера и не давать анализируемому файлу управлять ими. В автономном JSON/форме пользователь может ввести вымышленные записи. Совпадение hash доказывает лишь привязку записи к указанным байтам, не истинность pass. Сервер, подпись записей и запуск внешних тестов в v0.3 не реализованы.

Результаты:
- blocked: records отсутствуют/не подходят;
- review: нужен человек, модель не подключена или уверенность между порогами;
- needs_context: слабая лексическая поддержка (`low_lexical_support`) или усечённый вход;
- demo_only: синтетическая модель, записи подходят;
- candidate_for_review: несинтетическая модель, YES выше эффективного порога и записи подходят.

Везде **can_apply:false**. Нет auto-execute/apply/rollback. Все результаты — рекомендации для ревью. Нет запуска APK, shell или кода из state.

Ответ: при пригодном покрытии YES при p>0.5 и p>=effective, NO при p<0.5 и p<=1-effective, иначе unknown (`confidence_below_threshold`). Эффективный порог = max(threshold, 0.5), зоны YES/NO не пересекаются; запрошенный порог сохраняется в `threshold`, применённый — в `effective_threshold`, сравнение — в `above_threshold`. При threshold<=0.5 выдаётся предупреждение; для guardrail предпочитай высокий порог. Threshold не является обещанием безопасности или установленной долей ошибок. Отчёт содержит `abstention_reasons`, `fields` с unknown_words/truncated, `entropy/logit`, `contributions` (топ-12) и `model` (версия, схема, число признаков, метрики).

## Тесты

```powershell
go test ./... -count=1 -cover
go test -race ./...
go vet ./...
go test ./textai -run '^$' -fuzz FuzzTextNoPanic -fuzztime=3s -parallel=2
.\bin\decision-ai.exe test -input examples\tests.json
```

Проверяются прежний структурированный режим, текст/JSON, обучение и сохранение, разделение групп, дубликаты, unknown vocabulary, чужой question, stale hash, build/runtime fail, сервер, ownership, scope, отсутствие auto-apply, попытка инструкцией в state отменить hard gate, HTTP-токен/Host и loopback, эффективный порог, truncated, text-eval метрики и leakage.
