# Semantic v0.4 — классификатор «по смыслу» внутри DecisionAI

Без отдельного сайта: движок живёт в пакете [`semai`](../../semai/), спрашивается из CLI и из блока «Спросить по смыслу» на странице `/text` (та же тема дашборда, без градиентов и эмодзи).

```powershell
.\bin\decision-ai.exe ask -input examples\ask-cases.json
.\bin\decision-ai.exe ask-batch -input examples\ask-cases.json
.\bin\decision-ai.exe serve -text-model models\demo-text-model.json   # веса encoder/nli подхватываются из models/ сами
```

Без CGO, без внешних зависимостей, без сети и GPU. Веса — `models/encoder-tiny.dte` + `models/nli-tiny.dte` (≈ 48 МБ), происхождение и лицензии — [ENCODER-NOTICE.md](../../models/ENCODER-NOTICE.md). Нет весов — работает только символьный слой (в ответе `neural.enabled=false`).

## Как это устроено

1. **Transformer-энкодер** (`semai/encoder.go`, stdlib Go, BERT 3 слоя · 12 голов · d=312, int8-таблица слов): векторы предложений и токенов. Паритет с PyTorch покрыт тестами.
2. **NLI cross-encoder**: state и критерий кодируются вместе → `entailment / neutral / contradiction`. Различает «подтверждает / не связано / противоречит» по смыслу, а не по словам.
3. **Символьные решатели** (`partcount.go`, `arith.go`, `kb.go`): разбор чисел, объектов и вариантов; набор правдоподобных прочтений с весами. Прочтения разошлись — ответ `unknown` (как с 3,5 мыши: A 20% / B 40% / C 40% → unknown).

Честные ограничения: NLI точен на 60–74% тестовых выборок и переуверен — поэтому смешан с эвристикой и подчинён порогам; приоры прочтений — экспертные, не выученные; вне таблицы знаний — `unknown`, а не выдумка. Это не LLM (29 млн параметров). Гейт патч-режима этот слой не отменяет.

Переобучение и конвертер весов без torch: `scripts/convert_encoder.py`, `scripts/convert_nli.py`, `scripts/train/` (генерация доменных пар и обучение NLI-головы).


## Страница «Спросить» и solve — v0.5

Одно поле: вопрос. Условие и файлы добавляются по желанию. Всё уходит в
`POST /api/solve` (CLI: `decision-ai solve -q "…" [-context "…"] [-dir папка]`):

1. **Есть файлы** → `PickDoc`: какой файл отвечает на вопрос, с вероятностями
   и вариантом «ни один». Учитывает BM25 по словам и частям camelCase, словарь
   технологий, небольшой ru→en глоссарий и имя файла.
2. **Факты** → `SolveFacts`: «хватит ли денег / может ли купить» и «хватит ли
   X на всех Y». Ответ всегда с расчётом; если чего-то не хватает — «не знаю».
3. **Иначе** — смысловой режим (варианты A/B/C, арифметика, критерии).

Лексический классификатор патча живёт рядом как был: `/api/text`,
`decision-ai text-analyze`, дашборд на `/text`.
