# Тетрис и русские шашки

Два новых решателя подключены к `dai game`, `POST /v1/game`, эксперту `game_move`
и игровому циклу MCP. Дополнительные модели, GPU и библиотеки не нужны.
Обычный текстовый ансамбль не изменяется этими решателями.

## Запуск

```powershell
go build -o .tmp/dai-games.exe ./cmd/dai
.\.tmp\dai-games.exe game -input examples/games/tetris.json
.\.tmp\dai-games.exe game -input examples/games/russian-checkers.json
.\.tmp\dai-games.exe serve -light
```

Есть [визуальная игровая на /games](VISUAL-ARENA.ru.md): ИИ читает тетрис и шашки
по PNG видимого поля. Ниже описан низкоуровневый формат состояния и правила
решателей. Он остаётся доступен для явно структурированных интеграций.

## Тетрис

```json
{
  "game":"tetris",
  "piece":"I",
  "next":"T",
  "grid":["..........","..........","..........","..........",
          "#########.","#########.","#########.","#########."]
}
```

`grid` содержит только закреплённые блоки `#` и свободные клетки `.`;
текущая фигура и её тень в поле не включаются. Размер: 4–16 столбцов, 4–24 строки.
Запрос делается после очистки предыдущих заполненных рядов. `piece` — одна из
`I`, `O`, `T`, `S`, `Z`, `J`, `L`; `next` — необязательная следующая фигура.

Без `active` фигура появляется в состоянии поворота 0, в позиции
`x = width/2 - 2`, `y = -2`. Начало координат — слева сверху, Y растёт вниз.
Для уже движущейся фигуры передайте `active:{"x":3,"y":4,"rotation":1}`.
Координаты относятся к локальной сетке фигуры SRS (4×4), не к левой занятой клетке.
Повороты 0, 1, 2, 3 соответствуют 0°, 90°, 180°, 270° по часовой стрелке.
Для O используется только rotation 0.

Алгоритм проверяет достижимость через сдвиги, спуск и повороты SRS со смещениями
у стен. Затем оценивает дырки, суммарную/максимальную высоту, неровности,
глубину колодцев и очищенные линии. Для четырёх лучших вариантов дополнительно
проверяется известная следующая фигура.

Ответ включает:

- `action` — идентификатор вида `place_1_7_16` (поворот, X, Y);
- `placement` — конечная позиция;
- `controls` — достижимая последовательность `left`, `right`, `down`, `cw`, `ccw`,
  завершающаяся `hard_drop`;
- `cleared` — число рядов, которые очистит текущая фигура;
- `search` — расход бюджета, завершённая глубина 1/2 и признак ограничения.

Адаптер должен выполнить `controls` с корректным для игры временем нажатий.
Это план клеточных перемещений: реальная гравитация, DAS/ARR и ограничение сбросов
таймера фиксации могут потребовать более частых наблюдений и перепланирования.
Hold, T-spin/комбо-очки и неизвестная очередь фигур пока не учитываются.
При `terminal:true, outcome:"top_out"` размещение не выбрано.

## Русские шашки

```json
{
  "game":"russian_checkers",
  "player":"white",
  "board":[".b.b.b.b","b.b.b.b.",".b.b.b.b","........",
           "........","w.w.w.w.",".w.w.w.w","w.w.w.w."]
}
```

Поле 8×8: `w`/`b` — белая/чёрная шашка, `W`/`B` — дамка, `.` — пусто.
Строка 0 соответствует восьмой горизонтали. Белые идут к строке 0, чёрные — к 7.
Игровые клетки имеют `(x+y)%2 == 1`, например a1 и b8.
`player` обязателен: `white` или `black`.

Реализованы правила русских шашек:

- взятие обязательно; простой ход при наличии взятия исключается;
- простая шашка бьёт вперёд и назад, дамка ходит и бьёт по всей диагонали;
- цепочка взятий завершается полностью;
- шашка становится дамкой при достижении последнего ряда и продолжает взятие
  уже как дамка;
- взятые фигуры блокируют линии до конца хода; повторно брать их нельзя;
- допускается любая полная цепочка: требование максимального числа взятий
  из других разновидностей шашек здесь не применяется.

Ответ содержит `action` в нотации `a3-b4` или `a3xc5xe7`, полный `path` и список
взятых клеток `captures`. Координаты `path`/`captures`: X/Y от нуля, Y сверху вниз.
Отправляйте всю цепочку одним логическим ходом. Входное состояние должно быть
между ходами, не посреди незаконченного взятия.

Оценка учитывает материал, дамки, продвижение и центр. Поиск с alpha-beta
отсечениями постепенно углубляется до 6 полуходов, сохраняя результат последнего
полностью законченного прохода. Повторы и турнирные правила ничьей по истории
партий не определяются по одному снимку поля; это задача игрового адаптера.

## Скорость и пределы

Поиск ограничен 18 мс по настенным часам и количеством операций: 16 000 для
тетриса, 12 000 для шашек. Проверка времени периодическая, поэтому это не жёсткая
квота ОС. При исчерпании бюджета возвращается уже найденный законный ход с
`search.limited:true`; если законный вариант ещё не найден, возвращается ошибка.
Отмена HTTP-запроса прерывает поиск.

`heuristic:true` означает ограниченную оценку, а не доказанную оптимальную игру.
В `/v1/decide` такие ответы направляются на `review`, даже при единственном
выбранном варианте. Это не заявление о силе гроссмейстера или гарантии выживания
на любом уровне тетриса.

Лёгкий сервер сохраняет один worker и мягкий лимит Go-памяти 64 MiB. CPU зависит
от числа ходов в секунду. Замеры выполняются отдельным процессом без параллельных
тестов; нельзя переносить старые замеры крестиков-ноликов на новые игры.

```powershell
python scripts/measure_game_budget.py --binary .tmp/dai-games.exe --game tetris
python scripts/measure_game_budget.py --binary .tmp/dai-games.exe --game russian_checkers
```

Предыдущий замер структурированных запросов 15.10.2026, Windows, i5-3340 (4 CPU), по 24 HTTP-запроса
каждой игры при двух запросах в секунду, без параллельных тестов:

| Показатель | Тетрис | Русские шашки |
| --- | ---: | ---: |
| Первый запрос после готовности сервера | 3,3 мс | 3,7 мс |
| Медиана / p95 | 3,2 / 11,2 мс | 3,7 / 27,9 мс |
| Максимум в прогоне | 21,5 мс | 57,3 мс |
| Пик рабочей памяти процесса | 18,8 МБ | 20,2 МБ |
| Частная выделенная память | 55,1 МБ | 56,9 МБ |
| Средний CPU всей машины | 0,54% | 0,31% |

Для тетриса использовалась позиция с очисткой четырёх рядов и следующей фигурой;
для шашек — начальная позиция. Это измерения этих сценариев, не всех возможных
позиций или всей внешней игры. Выброс 57,3 мс означает, что строгий потолок 50 мс
не подтверждён. Микрозамеры поиска без HTTP также выполнены; их результат зависит
от загрузки машины и срабатывания временного бюджета.

Отчёты: `checks/tetris-budget.json`, `checks/russian-checkers-budget.json`.
`go test ./... -count=1` и `go vet ./...` прошли. Журнал полного набора тестов:
`checks/tetris-checkers-tests.txt`.

## MCP

Можно сохранить явные сопоставления `actions`, либо указать один разрешённый
`move_tool`. Этот инструмент принимает `{"decision":{...полный ответ решателя...}}`.
Его `inputSchema` проверяется перед вызовом. Не задавайте оба способа одновременно.

Пример конфигурации для своего MCP-адаптера тетриса:

```json
{
  "server":{"command":"PATH_TO_YOUR_GAME_MCP"},
  "game":"tetris",
  "observation_mode":"structured",
  "observe":{"name":"observe_game","arguments":{}},
  "move_tool":"apply_game_decision",
  "max_steps":100,
  "min_step_interval_ms":500
}
```

В адаптере `apply_game_decision` выполняет `decision.controls` для тетриса или
`decision.path` для шашек. После выполнения DecisionAI запрашивает новое состояние.
Для шашек можно задать `player:"white"`; на ходе чёрных цикл завершится со статусом
`waiting_for_opponent`. Игра с противником в реальном времени требует повторного
запуска/возобновления после его хода.

Передавайте `revision` (строку с номером хода/тика) в наблюдении, если одинаковое
поле может законно появиться снова. Например, тетрис после очистки рядов может
вернуться к прежнему виду. Без изменения состояния цикл останавливается с
`no_progress`; он не повторяет действие вслепую.
