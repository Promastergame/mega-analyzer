# Пакет исправлений DecisionAI — 16.10.2026

Это исправление исходников из приложенного AI.zip, а не новая обученная модель.
Основная версия API сохранена: 1.17.0. Веса и существующие калибровочные файлы не заменялись.

## Быстрый старт в Windows

Полный архив распаковать в НОВУЮ папку. Исходную рабочую папку сохранить.
В полном архиве есть `bin/dai-go.exe`: Windows amd64, без CGO/AVX-зависимостей.
Он кросс-компилирован из исправленного кода; запуск Windows здесь не проверялся.

```bat
RUN-DAI.cmd serve
```

Открыть http://127.0.0.1:7480/playground, /collect или /games.
В чистой папке запускается Go-версия. Для ускорения при установленных Go, Nim 2.2.x,
MinGW и наличии AVX:

```bat
BUILD-NIM-WINDOWS.cmd
RUN-DAI.cmd serve
```

Локально подтверждены Linux amd64, Go 1.22.12, Nim 2.2.4, FASM-путь с уже
поставленным `nim/fagemm.o`. Скрипты .cmd и Windows native runtime не запускались.

Маленький patch-архив содержит только изменённые/новые исходники и отчёт, без
весов и исполняемого файла. Его накладывать только на резервную КОПИЮ исходного
AI.zip. После наложения обязательно пересобрать: старые .exe не обновляются сами.

## Что изменено

### Разметка и обучение прототипов

- Идентификатор примера включает SHA изображения, его размеры, координаты области
  и класс. Разные области одного класса больше не склеиваются.
- Для одной области/класса действует последняя валидная метка из JSONL.
  Исправленный голос удаляет вклад прежнего голоса; статистика пересчитывается.
- Новые примеры добавляются инкрементально. Пересчёт ограничен максимумом 4096
  актуальных обучающих примеров. Исправления принимаются и при заполненном лимите.
- Исправление без вектора удаляет прежний обучающий пример, сохраняя аннотацию
  в журнале. Старый журнал не переписывается и не удаляется.
- Повторный одинаковый голос не расходует дополнительный активный лайк.
  Бюджет — максимум пять актуальных положительных аннотаций на изображение;
  дизлайк освобождает соответствующий активный лайк.
- Изменение явной adult/safe-метки не оставляет обе старую и новую метки в модели.
  Дизлайк класса сам по себе НЕ является меткой safe.
- Модель владеет копиями векторов и указательных значений; буферы запроса не
  удерживаются как изменяемое состояние. `saved` и `learned` остаются разными полями.

### Калибровка и автоматические действия

DTE получает SHA-256 точных байтов файла; для файла с заимствованной таблицей
в идентификацию входит и отпечаток базовой модели. В идентификацию ансамбля
входят все участники, Scale/Bias и версия признаков. Конфигурация дополнительно
учитывает retrieval-бюджеты, lexical fusion, имена экспертов и содержимое
реестра навыков/примеров. CLI хеширует файлы моделей экспертов и ленивой модели
навыков без создания их тензоров.

В калибровку записывается `fingerprint`. Отсутствующий или несовпадающий отпечаток
ограничивает нейросетевой маршрут уровнем `review`; ответы `human` не повышаются.
Проверенные детерминированные эксперты сохраняют собственную политику.
`/v1/health` показывает `configuration_fingerprint` и `calibration_issue`.

ВАЖНО: старые файлы калибровки намеренно не помечены проверенными автоматически.
Их температуры остаются доступными для совместимости, но нейросетевой `auto`
с ними запрещён. Это снижение автоматизации ради безопасности, не рост точности.

Для повторной калибровки используйте ОТДЕЛЬНЫЙ разрешённый размеченный набор,
не held-out тесты. Сохраняйте результат в новый файл и проверяйте его отдельно:

```bat
bin\dai-go.exe calibrate -input YOUR_CALIBRATION.jsonl -output models\my-calibration.json
bin\dai-go.exe serve -calib models\my-calibration.json
```

Все флаги моделей, экспертов, lexical fusion и навыков при калибровке и запуске
должны совпадать. Для допуска `auto` сохраняется прежний минимум 50 примеров
соответствующего типа. `skills-calibrate` не переносит старые температуры других
типов в новую конфигурацию, если прежняя калибровка не совпадает.

Go API: пользовательский backend должен реализовать `Fingerprint() string` либо
получить корректный `Engine.ModelFingerprint`. Внешние модели экспертов/ленивых
навыков требуют корректного `AuxiliaryFingerprint`. Менять веса/параметры в
параллельном inference нельзя. `BindCalibration` предназначен ТОЛЬКО для нового
результата калибровки, не для проставления отпечатка старому файлу.

### Проверяемые вычисления

Для уже поддержанных типизированных задач величин добавлено необязательное поле
`answer.calculation`: исходные нормализованные значения, факты со строками
оснований, операции, доступное/требуемое количество и дефицит.
`CalculationTrace.Verify()` независимо пересчитывает арифметическую цепочку.
Некорректный протокол запрещает автоматический ответ.

`verified` означает арифметическую согласованность, а НЕ независимое доказательство
истинности извлечённых фактов. Это не универсальный решатель всех рассуждений и
не автоматически сгенерированный «ход мыслей». Другие эксперты могут не иметь
поля calculation. Единицы в протоколе нормализованы: mass=g, volume=ml,
length=mm, time=seconds; RUB/USD/EUR сохраняют соответствующую валюту.
Нефинитные и переполняющие вероятности экспертов отклоняются.

### Контекст и скорость

- `TokenCount` считает подслова без скрытого ограничения maxPos.
- Слишком длинное слово разбивается на Unicode-фрагменты; хвост не отбрасывается.
  Если токеновый бюджет невозможен даже для одного символа, движок возвращает
  явную ошибку, а не молча обрезанный контекст.
- При ранжировании отдельно учитываются точное слово и слабое совпадение по
  пятисимвольной основе. Односимвольные числа больше не игнорируются.
  Суммирование признаков детерминировано.
- Неизменяемый индекс документа кэшируется в LRU с бюджетом 4 МиБ на Engine.
  Копии Engine разделяют этот кэш; разные движки независимы. Слишком большой
  индекс не сохраняется. Бюджет — учтённая память кэша, НЕ ограничение всей RAM.
- Go API: `SetContextCacheLimit(bytes)`, `ContextCacheUsage()`. Ноль отключает
  удержание индекса. Настройки должны выполняться до начала обслуживания.
- Отмена запроса проверяется при построении и выборе контекста. Это не обещает
  прерывание уже начатой нативной матричной операции.

### Сервер и сборка

`/v1/decide`, `/v1/see` и `/v1/game` имеют общий лимит два активных запроса.
При перегрузке — HTTP 429 с Retry-After; неограниченная очередь не создаётся.
`/v1/health` доступен отдельно. Это не системный лимит памяти и не глобальный
лимит всех HTTP-обработчиков. Удалённое развёртывание по-прежнему требует своей
защиты сети/TLS; настройки доступа не расширялись.

Сборки разделены на `dai-go` и `dai-native`. Новый бинарник сначала создаётся
как candidate; после тестов кандидат заменяет бинарник соответствующего типа.
Нативный и Go-файлы не затирают друг друга и не затирают старый `dai.exe`.
Linux native script проверен реальным запуском. `RUN-DAI.cmd` выбирает native,
если он существует, затем Go; для проверки именно Go запускать `bin\dai-go.exe`.

В CI выделен отдельный обязательный native job: падение старого quality gate
не пропускает нативные проверки. Пороги качества не снижены.
