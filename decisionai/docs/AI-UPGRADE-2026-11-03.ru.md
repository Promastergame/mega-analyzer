# DecisionAI 1.20: вывод по фактам и локальный фильтр изображений

Добавлен маршрут `task=reasoning`. Он выполняет вывод из фактов и правил,
возвращает шаги доказательства с источниками и отличает подтверждение,
опровержение, отсутствие сведений и противоречие. Это исполнитель проверяемых
операций; нейронные веса этим обновлением не переобучаются.

## Как попробовать

После пересборки `go build -o bin/dai.exe ./cmd/dai` запустите
`bin/dai.exe serve` и откройте `/playground`. Первый сценарий «Цепочка фактов»
показывает ответ «Да», обратный ответ «Нет» и отдельный отказ из-за нехватки
данных. Шаги и следующие проверки видны прямо в карточке ответа.

Для обычных вопросов без `task` и описаний `criteria` модуль также включается,
если вопрос полностью разобран как сравнение и в исходном тексте найдены связанные факты. Остальные
запросы продолжают обрабатываться существующими экспертами и текстовой моделью.

Простой запрос к `/v1/decide`:

```json
{
  "state": "Лена выше Тимура. Тимур выше Олега.",
  "questions": {
    "height": {
      "type": "noul",
      "task": "reasoning",
      "instructions": "Лена выше Олега?"
    }
  }
}
```

Поддерживаются отдельные полные предложения на русском и английском:
сравнения роста, возраста, веса, размера, скорости, порядка событий и вложения.
Обратные сравнения нормализуются, а явное «не» сохраняется. Даты `today`,
`yesterday`, `tomorrow` и русские эквиваленты разделяют факты по времени.
Несколько условий, местоимения и произвольная проза не превращаются в факты.
Склонения имён сопоставляются только с однозначными сущностями этого запроса.

Для произвольных предикатов используйте JSON-факты и правила:

```json
{
  "state": {
    "facts": [
      {"subject":"mira","predicate":"paid","source":"receipt"},
      {"subject":"mira","predicate":"verified","source":"identity"}
    ],
    "rules": [
      {
        "all": [
          {"subject":"$person","predicate":"paid"},
          {"subject":"$person","predicate":"verified"}
        ],
        "then":{"subject":"$person","predicate":"ready"},
        "source":"access-policy"
      }
    ]
  },
  "questions": {
    "access": {
      "type":"noul",
      "task":"reasoning",
      "instructions":"Проверить доступ",
      "claim":{"subject":"mira","predicate":"ready"}
    }
  }
}
```

Результат содержит `reasoning.proof`: два исходных факта и вывод из них.
Источники задаёт вызывающая сторона; доказательство проверяет логическую
связь, а не достоверность квитанции или других исходных сведений. Для `choice`
каждый обычный вариант должен описывать утверждение; `abstain_key=unknown`
позволяет явно вернуть отсутствие единственного подтверждённого варианта.

Факты из `current` отделены от архивных данных. Явное отрицание обязательно:
отсутствующий факт не считается ложным. Противоречивые предпосылки исключены
из дальнейших выводов; независимое доказательство может восстановить вывод.
При отключённом эксперте структурный запрос не подменяется текстовым прогнозом.
Ответы этого маршрута сохраняют локальное доказательство при эскалации.

На запрос выделены 512 сохранённых шагов, 128 правил, до 8 предпосылок в
правиле, 16 раундов и 50 000 проверок сопоставления. При достижении лимита
возвращается отказ. Повторно используемые части доказательства обходятся один
раз при проверке, поэтому общий граф предпосылок не вызывает экспоненциальный
обход.

Название источника правила служит только меткой в доказательстве. Даже метка
`transitivity:taller` в пользовательском правиле не переопределяет встроенный
вывод и не меняет допустимость его заключения.

## Свойства команд

Однозначные вопросы без `task` и произвольных `criteria`, например
«Does the call only read data without changing anything?», получают разбор
простого `shell(...)` из строки `Proposed tool call:` или поля `tool_call`.
Поддерживаются чтение через `df`, `ls`, `cat` и другие известные команды,
ограниченный `git log`, а также операции изменения файлов и репозитория.
Сложные выражения, подстановки, перенаправления, неизвестные обёртки и
неоднозначные вопросы остаются у существующей модели.

Разбор описывает стандартное действие команды и сохраняет её исходную строку
в объяснении. Он не запускает её и не устанавливает полномочия вызывающей
стороны. Этот эксперт не помечает свои ответы как основание для маршрута `auto`.

## Изображения

Политика превью обновлена до версии 2; клиент Mega-Analyzer принимает версии
1 и 2. Цветовой фильтр измеряет вариативность именно совпавших пикселей и
отдельных компонентов. Красный однотонный логотип больше не заимствует
«текстуру» окружающей фотографии. Локальный текстурный участок может включить
защиту при площади от 2% для тёмного класса и от 3% для яркого, даже если
общий скор ниже прежнего порога. Однотонные компоненты пропускаются.

Области размытия получают небольшой запас по краям и ограничиваются размерами
исходного изображения. В `/collect` размываются найденные области, есть кнопка
«Показать оригинал». Если координат нет, остаётся размытие всего превью.
Исправлены потерянные ID выпадающих списков, мешавшие запуску режимов и загрузке
модели в Vision Studio.
При смене режима класс ручной области автоматически выбирается из доступных
вариантов, поэтому список больше не остаётся пустым после добавления объекта.

Фильтр остаётся цветовой эвристикой: его скор не является вероятностью и не
доказывает, что изображён именно биологический объект. Проверки локального
участка и ложного совпадения используют синтетические изображения; качество
на размеченных настоящих фотографиях этим обновлением не измерялось.

## Проверки

```powershell
go test ./... -count=1
go vet ./...
python -m unittest discover -s scripts/data -p "test_*.py"
python -m unittest discover -s scripts/distill -p "test_data_checks.py"
bin/dai.exe eval -backend lexical -input evals/reasoning-proof.jsonl -min-noul 1 -min-choice 1
```

Новый набор `evals/reasoning-proof.jsonl` проверяет два языка, несколько типов
отношений, отрицания, время, правила с общими переменными, выбор и отказ.
Отдельные регрессионные тесты проверяют противоречия, независимые доказательства,
лимит вычислений, локальную текстуру, границы и повторные метки обратной связи.
Интерфейс проверяется с реальным локальным сервером через `agent-browser`.

На этой рабочей копии новый набор дал 25/25 правильных ответов. Все семь
существующих порогов CI пройдены на 719 вопросах. На JeV точность `noul`
выросла с 87,78% до 88,15% при прежнем пороге 88%; остальные показатели
совпали с предыдущей сборкой. Это небольшой прирост на данном наборе,
а не оценка качества модели на любых вопросах.

Полный набор Go-тестов DecisionAI, `go vet` и 14 Python-проверок данных
пройдены. В браузере проверены карточки доказательств, загрузка состояния
Vision Studio, размытие локального участка, показ оригинала и однотонный
логотип без маски. Общий запуск Mega-Analyzer также проверил остальные
пакеты; ограничения доступа Windows устранены повторным запуском вне
песочницы. В старых тестах `pkg/internal/apkloader` сохраняется нестабильная
очистка временных каталогов (`The directory is not empty`) даже при
последовательном запуске; исходники этого пакета данным обновлением не меняются.

## Git

Веса `.dte`, checkpoint-файлы, сгенерированные датасеты и ответы учителей,
`.runtime`, `.tmp`, `checks`, логи сессий и нумерованные `.bak` исключены из
новых коммитов. Небольшие рабочие JSON-модели, калибровки, исходники, тесты,
описание датасета и вручную подготовленные перефразы остаются в Git. Локальные
файлы не удаляются. На этой рабочей копии только веса и сгенерированные данные
составляли около 395 МиБ.

Старые сборки и архивы уже находятся в истории Git. `.gitignore` предотвращает
новые добавления, но не удаляет такие объекты из существующих коммитов.
