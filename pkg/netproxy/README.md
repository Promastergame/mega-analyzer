# netproxy

Лабораторный MITM-прокси для `mega-analyzer`, разбитый на несколько файлов вместо одного монолита.

## Структура

| Файл | Ответственность |
|------|-----------------|
| `doc.go` | Пакетная документация и карта файлов |
| `config.go` | `AdvancedMITMConfig`, валидация, дефолты |
| `mitm.go` | Структура `AdvancedMITMProxy`, `New`, трекинг соединений, `Close` |
| `ca.go` | `CertificateAuthority`: генерация/загрузка лабораторного CA |
| `leaf.go` | Выпуск листовых сертификатов на хост |
| `certcache.go` | Кэш + single-flight генерация листовых сертов |
| `intercept.go` | Перехват TLS + relay с лимитами (`copyWithLimits`) |
| `ja3.go` | Захват метаданных ClientHello (НЕ канонический JA3) |
| `secrets.go` | Поиск секретов по скомпилированным regex |
| `allowlist.go` | Allowlist / offline-политика + разбор хоста |
| `events.go` | Канал событий MITM |
| `engines.go` | Типы данных inference / replay / fuzzing |

### Соседний функционал (транспарентный записывающий прокси — ваши файлы)

| Файл | Ответственность |
|------|-----------------|
| `proxy.go` | `TCPProxy` + `PacketRecorder` (кадрированная запись трафика) |
| `udp_proxy.go` | `UDPProxy` с NAT по сессиям и упорядоченной пересылкой |
| `policy.go` | Offline-by-default политика upstream для TCP/UDP-прокси |
| `editor.go` | Интерактивный редактор пакетов |
| `msgpack.go` | Хелперы инспекции MessagePack |

## Что исправлено относительно исходного монолита

### Баги
1. **JA3 key = `UnixNano`** — коллизия в один тик затирала запись. Теперь ключ `UnixNano-<atomic seq>` (`ja3.go`).
2. **Relay рвал half-close** — форс-дедлайн ставился на обе стороны даже при чистом EOF, обрезая живое направление. Теперь `CloseWrite` на завершившуюся сторону + grace-таймаут только как крайняя мера (`intercept.go`).
3. **`Close()` мог зависнуть навсегда** — закрывались только листенеры. Теперь активные соединения трекаются и принудительно закрываются перед `wg.Wait()` (`proxy.go`).
4. **ALPN не пробрасывался** — h2-клиент мог отвалиться / тихо даунгрейдиться в http/1.1. Теперь клиентский ALPN зеркалится, а согласованный протокол уходит в upstream `NextProtos` (`intercept.go`).
5. **`caCertPEM` хранил DER** — при отдаче клиенту как PEM получался битый файл. Поле переименовано в `caCertDER`, добавлен `CACertPEM()` (`ca.go`).
6. **Single-flight не переживал панику** — паника в keygen оставляла запись в `certInflight` и вечно вешала вейтеров. Теперь `defer` с `recover` всегда чистит inflight и будит вейтеров (`certcache.go`).
7. **`loadCA` не восстанавливал constraints** и не проверял `IsCA` — теперь `permittedDNSDomains` берётся из реального серта, есть проверка `IsCA` и поддержка PKCS8 (`ca.go`).

### Безопасность / поведение
8. **Allowlist пускал весь loopback/private безусловно** (SSRF во внутреннюю сеть) — теперь только при `AllowPrivateAddrs=true` (`allowlist.go`). **Это изменение поведения:** для локальной лабы выставите флаг.
9. **Upstream TLS всегда верифицировался** — ломало перехват целей с self-signed сертами. Добавлен `InsecureUpstreamTLS` (`config.go`, `intercept.go`).
10. **`EnableCertPinningBypass`** помечен `Deprecated` — серверным TLS pinning не обходится.

13. **Нет проверки размера буферов в relay** (ваш репорт) — голый `io.Copy(dst, src)` не имел ни лимита байт, ни таймаута, ни потолка памяти: большой/зависший трафик мог течь вечно и раздувать память. Заменён на `copyWithLimits` (`intercept.go`) с тремя предохранителями:
    - **максимальный размер захвата** — `MaxBytesPerConn` (по каждому направлению, `0` = без лимита);
    - **таймауты** — `RelayIdleTimeout` (per-read дедлайн, по умолчанию 5 минут, чтобы зависшее соединение всегда рано или поздно освобождалось);
    - **лимиты памяти** — фиксированный буфер 32 KiB, так что один `Read` не может форсировать огромную аллокацию.

    То же самое `TCPProxy` (`proxy.go`) уже имеет иначе: кадры ограничены `maxFrameSize` (16 MiB) и стоит 30-секундный read-дедлайн.

### Улучшения
11. `SecretScanner` компилирует regex один раз; паттерны сужены до key=value/форматов токенов (меньше ложняков).
12. Валидация `FuzzingMutationRate`/`MaxActiveConns`/`MaxBytesPerConn`; таймаут TLS-хендшейка; лимит одновременных соединений (`sem`).

## ⚠️ Важно: конфликт имён при распаковке

Вы распаковали мой первый архив **поверх** своего проекта, где уже был исходный монолит `advanced_mitm.go`. Он дублировал все типы/функции из разбитых файлов → пакет не собирался. В этой версии `advanced_mitm.go` **удалён**, а жизненный цикл `AdvancedMITMProxy` перенесён в `mitm.go` (ваш `proxy.go` с `TCPProxy` не тронут — это другой функционал).

Тесты `netproxy_more_test.go` обновлены: там, где проверяется автоallow для localhost/loopback, теперь выставлен `AllowPrivateAddrs: true` (иначе с новым SSRF-дефолтом они бы падали).

14. CA получил `MaxPathLenZero` (не может подписывать промежуточные CA); ключ/серт пишутся с `Sync()`.

## Известные ограничения

- Это **не** настоящий JA3: `crypto/tls` не отдаёт порядок расширений. Для канонического JA3/JA4 нужен разбор сырого ClientHello (`utls` или ручной парсинг первого record).
- Name Constraints ограничивают только DNS-имена; IP-SAN листы не ограничены — для containment используйте только DNS-хосты.
- Поля UDP/QUIC/inference/replay/fuzzing — это каркас типов; исполняющая логика предполагается в других файлах пакета.

> ⚠️ Инструмент форжит сертификаты и перехватывает живой TLS. Используйте только против хостов, которые вы уполномочены перехватывать.
