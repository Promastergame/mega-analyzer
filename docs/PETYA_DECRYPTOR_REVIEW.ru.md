# Статический разбор PetyaDecryptor

Проверено 23 октября 2026 года. Исследована папка `PetyaDecryptor` в корне
проекта. EXE и DLL из неё не запускались, не загружались как библиотеки и
не эмулировались. Использовались чтение байтов, SHA-256, разбор PE и дизассемблирование.
Исходная папка не изменялась.

## Происхождение

Все три бинарника **побайтово совпадают по SHA-256 с официальным выпуском
hasherezade petya_key v0.2**. Официальный ZIP был получен по HTTPS и разобран
в памяти, без извлечения или запуска программ.

Источник: [выпуск 0.2](https://github.com/hasherezade/petya_key/releases/tag/0.2).

## Как восстанавливается ключ

Программа использует **закрытый мастер-ключ старой Petya, опубликованный Janus**.
Он встроен в программу. Она не ищет его в запущенном вирусе и не перебирает
все возможные ключи AES.

1. Читает одну строку ID жертвы из переданного текстового файла и спрашивает
   вариант: Red Petya, Green Petya/Mischa или GoldenEye.
2. Убирает служебные символы ID по правилам выбранной версии и декодирует Base58.
3. Из результата берёт 49 байт открытого ключа жертвы на эллиптической кривой
   и следующий 16-байтовый блок с зашифрованным ключом.
4. Вычисляет общий секрет через **ECDH/secp192k1**, используя открытый ключ
   жертвы и опубликованный закрытый ключ Janus.
5. Воспроизводит особое расширение секрета из Petya, затем вычисляет SHA-512.
   Первые 32 байта результата используются как ключ AES-256.
6. Расшифровывает 16-байтовый блок в режиме AES-ECB. Для Red/Green дополнительно
   применяет XOR с первыми 16 байтами открытого ключа жертвы.
7. Печатает восстановленный ключ: строкой из 16 символов для Red/Green,
   шестнадцатеричными байтами для GoldenEye.

Схема: **ID жертвы + опубликованный мастер-ключ → ECDH → SHA-512 → AES → ключ Petya**.

Основание: [исходник автора](https://github.com/hasherezade/petya_key/blob/master/src/main.cpp),
импорты OpenSSL и проверенный машинный код локального EXE. В бинарнике присутствуют
`ECDH_compute_key`, `SHA512_Init/Update/Final`, `AES_set_decrypt_key`, `AES_ecb_encrypt`.
24-байтовая константа опубликованного закрытого ключа найдена по файловому
смещению `0x10600`, виртуальный адрес `0x412000`.

Контрольные точки дизассемблирования при базовом адресе `0x400000`:

| Адрес | Наблюдаемая операция |
| --- | --- |
| `0x401549` | Чтение файла ID и выбор варианта |
| `0x401582` | Передача адреса встроенного закрытого ключа |
| `0x4015FB` | Декодирование данных жертвы |
| `0x4016A3` | Получение общего секрета и его хеша |
| `0x4016DB` | Расшифровка блока ключа через AES |
| `0x401750` | Ветка XOR для Red/Green |
| `0x401710` / `0x40179E` | Вывод ключа в hex / текстовом виде |

## Где результат и что он означает

Ключ выводится в консоль после `[+] Your key`. Автоматического файла с ключом
в исследованном основном пути нет. Этот EXE восстанавливает ключ, а восстановление
MFT или отдельных файлов выполняется другим компонентом. Это также указано в
[README автора](https://github.com/hasherezade/petya_key#readme).

Поддерживаются конкретные старые семейства Red Petya, Green Petya/Mischa,
GoldenEye. **NotPetya этим инструментом не расшифровывается**. Опубликованный
ключ Janus не даёт ключи от произвольного современного ransomware.

В локальном `id_raw.txt` находится только инструкция-заглушка:

```text
(Enter the decryption code that the ransom note provided you, no - or spaces)
```

Настоящего ID жертвы здесь нет, поэтому в этой проверке ключ не вычислялся.

## Что полезно для Mega-Analyzer

Механизм подходит для отдельного офлайн-модуля восстановления ключей известных
семейств: определить поддерживаемую версию, строго проверить ID, применить
опубликованный мастер-ключ и сохранить результат в отчёт на хосте. Исполнение
образца или скачанного `petya_key.exe` такому модулю не требуется.

При переносе важны точное представление секрета перед SHA-512, различия
Red/Green/GoldenEye и проверка входных данных. В старом исходнике есть слабые
проверки длины и ошибок, поэтому переносить весь C++ код без пересмотра нельзя.
В рамках этого разбора такой модуль не добавлялся; исследованы устройство
утилиты и соответствие файлов официальному выпуску.
