# Модули и приоритеты улучшений

Состояние на 11 октября 2026. Начать разделение можно в текущем репозитории:
публичные Go-пакеты с небольшими контрактами, отдельные команды и общий набор
проверок. Отдельные `go.mod` нужны, когда появятся независимые зависимости,
потребители и версии. Сейчас их массовое введение усложнит работу с общими
типами и `internal`-пакетами.

## Что сделано в этой итерации

- Публичный [API декомпилятора](../pkg/decompiler/decompiler.go) и самостоятельная
  команда [cmd/decompiler](../cmd/decompiler/main.go). `analyzer decode` использует
  тот же контракт. Есть APK/DEX, JSON, отмена и ограничение времени.
- Оркестрация декодирования, обработка нескольких DEX и генератор Smali вынесены
  из `extractor.go` в `decode.go`, `decode_dex.go` и `smali_emitter.go`.
  Старый путь генерации Smali теперь использует тот же код записи и обработки
  коллизий имён, что и новый.
- Настройки заголовков и standalone передаются на каждый вызов. Режим native
  не запускает поиск внешних инструментов. Отключение кэша не отключает
  параллельную обработку DEX.
- Ошибки DEX, ресурсов и split APK возвращаются вызывающему коду.
  Декодирование использует только нативный backend.
  Старый маркер успешного декодирования удаляется до изменения артефактов.
- [Вердикт](../pkg/internal/verdict/verdict.go) учитывает отмену и ограничения
  data-flow: пропущенные методы, усечённые slices и неполные CFG. Подтверждённые
  находки сохраняют прежний приоритет; ограниченный анализ без находок получает
  статус `incomplete`.
- [Сравнение каталогов](../pkg/internal/diffengine/differ.go) считает объединение
  путей. Для `{old.txt}` и `{new.txt}` теперь `TotalFiles=2`, `Unchanged=0`.
  Отсутствующий или нечитаемый вход возвращает ошибку.
- [Граф доказательств](../pkg/internal/evidencegraph/graph.go) возвращает каждую
  связь один раз. Общий узел проекта не расширяет запрос по одному файлу на все
  остальные файлы. Настоящие межфайловые корреляции сохраняются; ограничения
  размера не оставляют связей с отсутствующими узлами.
- [AXML overlay](../pkg/internal/apkloader/axml/encode.go) принимает и префиксную
  (`android:name`), и разрешённую (`http://schemas.android.com/...`) форму
  пространств имён, потому что `encoding/xml.Token()` возвращает уже
  разрешённые URI. Новые элементы манифеста проверяются по списку известных
  тегов (`<permission>` и подобные без поддержки маппера отклоняются с
  `not supported`); для прочих корней ограничений нет.
- [ARSC редактор](../pkg/internal/apkloader/axml/arsc_edit.go) ищет `Res_value.data`
  по смещению `base+12`, а не `base+20`: запись имеет 16 байт, данные лежат сразу
  за 8-байтовым заголовком. Старое смещение выходило за конец чанка на
  синтетических таблицах и портило соседние записи при правке цветов.

Сборка `go list -tags noembed -deps` включает 29 пакетов проекта для отдельного
декомпилятора и 126 для анализатора, включая сами команды. Это уже позволяет
проверять декомпилятор отдельно. В его зависимости ещё входят `apkloader`,
общие типы и несколько пакетов анализа — полное отделение нижнего слоя впереди.

## Следующие границы модулей

| Приоритет | Модуль | Что отделять | Критерий готовности |
| --- | --- | --- | --- |
| 1 | Android formats | DEX, AXML/ARSC, таблицы инструкций, чтение/запись и небольшие типы результатов | Парсеры собираются без `pkg/ml`, отчётов, сетевого анализа и CLI; корпус round-trip проходит отдельно |
| 1 | APK build | Smali assembler, упаковку, ресурсы, подпись и выравнивание | Правка Smali/ресурса меняет финальный APK; подпись и выравнивание проверяются после упаковки |
| 1 | Analysis service | Выполнение скана из `runner.go` и `pipeline.go`, контекст запуска и статусы этапов | CLI/API/Web используют один `Analyze(ctx, Request)`; два скана не делят изменяемые настройки |
| 2 | Evidence/report | Нормализованную модель находок, вердикт, граф, сравнение и представления | Отчёт можно построить заново из сохранённого результата без повторного скана |
| 2 | Device sessions | ADB/Frida, запуск сеанса, события, отмену и завершение процессов | Вся сессия останавливается одним контекстом; записанный сеанс воспроизводится без устройства |
| 2 | ML inference | Загрузку модели и inference отдельно от обучения и истории | Отсутствие модели даёт явный статус; статический анализ собирается без обучающих компонентов |
| 3 | UI modules | API-клиент, состояние задания, файлы проекта и панели из `app.js`; команды и рисование Zig-редактора | Один жизненный цикл задания, обработка ошибок и отмены; UI-проверки запускаются независимо от движков |

`pkg/vulnscan` развивается параллельно и в этой итерации не изменялся.
Уже существующие `pkg/binzap` и `pkg/antivm` следует учитывать
как готовые границы, прежде чем создавать новые дублирующие оболочки.

## Что улучшать сквозным образом

**Состояние запуска.** У декомпилятора настройки уже локальны. Для анализа
следующими кандидатами остаются глобальный реестр деградаций в `verdict`,
настройки инструментов и модели. Их следует привязать к конкретной сессии.

**Сохранность проекта.** Текущий decode пишет в выделенный каталог. Следующее
улучшение — подготовка результата в соседнем временном каталоге и публикация
после проверки. Нужен явный контракт для повторного decode и пользовательских
правок, чтобы старые артефакты не смешивались с новыми.

**Полнота результата.** Для каждого этапа нужны состояния «выполнен»,
«пропущен настройкой», «не поддерживается», «ограничен» и «ошибка» с причиной.
Код завершения, JSON и UI должны получать их из одной модели. Исправление
data-flow вердикта закрывает конкретный дефект, но не заменяет такую модель.

**Кэш и производительность.** Сначала измерять время/память на одних и тех же
входах и проверять равенство результатов с кэшем и без. Отдельно проверить
согласованную запись общего class-cache при нескольких DEX, удаление старых
классов и смену настроек вывода. Изменения числа потоков сами по себе не
доказывают ускорение.

**Качество декомпиляции.** Добавлять положительные и отрицательные fixtures для
debug info, annotations, новых opcodes, исключений, payload и ресурсов с разными
qualifiers. Java/Kotlin-представление и полное восстановление исходного проекта
остаются отдельной задачей. Не считать наличие Smali доказательством полной
семантической эквивалентности.

**Размер файлов.** `app.js`, `tui.go`, `pipeline.go`, `report/builder.go` и
`dex_parser.go` содержат примерно по две тысячи строк, `paint.zig` — около 2,5
тысячи. Делить их следует по ответственности и тестируемому контракту. Само
уменьшение числа строк в файле не убирает зависимость между подсистемами.

## Проверка изменений

Новые регрессии воспроизводят ошибки вердикта, отрицательный счётчик diff,
дублирование и лишний обход графа. Проверки декомпилятора покрывают нативный
DEX без инструментов в PATH, несколько DEX, независимость одновременных
вызовов, смену настроек кэша, частичные ошибки и JSON команды.

В CI добавлена отдельная проверка декомпилятора с `CGO_ENABLED=0` и `noembed`
в существующую матрицу Windows/Linux/macOS. Общий Go race-прогон также
подхватывает новые тесты.

Команды запуска и границы текущей реализации: [DECOMPILER.ru.md](DECOMPILER.ru.md).
