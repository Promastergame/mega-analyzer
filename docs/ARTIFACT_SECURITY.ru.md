# Безопасность SVG и распаковки APK

SVG проверяется в основном статическом анализе, независимо от включения панели артефактов. Общий структурный детектор используется также для отметок в HTML-панели.

Обнаруживаются `<script>`, `<foreignObject>`, непустые атрибуты событий (`onload`, `onerror`, `onbegin`, `onend`, `onrepeat` и другие), исполняемые схемы в `href`/`xlink:href`/`src`, а также SMIL-анимация, меняющая ссылку на такую схему. XML-ссылки на символы и пробелы в атрибутах учитываются. Декларации `xmlns`, комментарии с примерами тегов и обычная анимация не считаются JavaScript.

Длинные кодированные блоки в комментариях, `metadata`, `desc` и координатах пути проверяются отдельно. Сигнатура DEX, ELF, PE или ZIP в декодированных данных даёт находку высокого уровня. Высокая энтропия без такой сигнатуры — слабый признак кодированных данных, а не доказательство C2, RAT или вредоносности. Это эвристика, а не универсальный детектор стеганографии.

SVG в HTML-отчёте остаётся внутри `<img>`/`Image`, затем рисуется на canvas. Байты SVG не вставляются в HTML как разметка. Предпросмотр исходника в веб-хранилище возвращает `text/plain`; скачивание возвращает `application/octet-stream` с `attachment`, `nosniff` и ограничивающим CSP. Ответ `/api/report/` получает `sandbox allow-scripts allow-downloads` без `allow-same-origin`, а также `connect-src 'none'`: интерфейс отчёта работает, доступ к API анализатора ограничен. Это ограничение HTTP-ответа; исходный скачанный SVG сохраняется без изменения.

Надпись «SVG Secure» заменена на «No active SVG indicators». Неполная или недоступная проверка помечается отдельно, в том числе у внешних артефактов.

Распаковка отклоняет абсолютные пути, компоненты `..`, пути Windows с диском/UNC и альтернативными потоками. Заблокированный путь записывается как `CRITICAL` с правилом `archive.path_traversal`. ZIP-ссылки также блокируются. Все операции создания каталогов, временных файлов и перемещения извлечённых файлов выполняются через `os.Root`, ограничивающий доступ выбранной папкой.

Размеры из ZIP проверяются до записи. Фактический поток распаковки ограничивается независимо от заголовков; отмена операции проверяется между чтениями. Файл заменяется только после успешной распаковки, проверки размера и CRC. Ошибки формата, неподдерживаемого метода сжатия и CRC дают находку `archive.invalid_data`; превышение лимита — `archive.resource_limit`.

Лимиты на один архив: до 200 000 записей, 5 ГиБ суммарного извлечения, 3 ГиБ на обычный файл, отношение распаковки до 10 000. Более строгие пределы для разбираемых ресурсов: SVG — 8 МиБ, XML — 64 МиБ, ARSC — 256 МиБ. Основное чтение файла в память для статического анализа ограничено 64 МиБ (SVG — 8 МиБ); пропуск по этому пределу остаётся видимым в результате. Потоковая обработка DEX использует собственные ограничения. Кеш декодирования обновлён, чтобы старые результаты прошли новые проверки.

Наличие логотипов и методов `getBrandLogoSvg`/`getDeviceBrand` само по себе не доказывает фишинг или выполнение JavaScript. Доступ SVG к Java bridge зависит от способа вставки, происхождения документа и настроек WebView. Исполнение требует отдельного подтверждения.
