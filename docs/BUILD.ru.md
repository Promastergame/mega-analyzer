# Сборка Mega-Analyzer

[English](BUILD.md)

Mega-Analyzer поставляется в двух разных сборках. Выбирай ту, что соответствует
задаче — большинству пользователей нужна только **core-сборка**.

| Сборка | Что получаешь | Что нужно |
| :--- | :--- | :--- |
| **Core** (по умолчанию) | Полный Go-анализатор: APK/DEX/Smali, аудит манифеста, триаж секретов, проверки харденинга PE/ELF, все отчёты (HTML/MD/JSON/SARIF). 100% чистый Go, без cgo. | Только Go 1.27.3+ |
| **Full native** | Core **плюс** нативный движок OmniSec (Rust: CFG/SSA/dataflow/символьное исполнение), Zig SIMD ML-рантайм и GNN-классификатор. Включается через cgo build-теги. | Go + Rust 1.96.1+ + Zig 0.17.0+ (и C-тулчейн) |

> Заглавные нативные движки (OmniSec, Zig ML, GNN) — **опциональные**, они закрыты
> cgo build-тегами. Обычный `go build` даёт core-анализатор, который уже является
> законченным самодостаточным инструментом. Rust и Zig **не нужны**, если только
> тебе специально не нужен путь нативного анализа машинного кода.

---

## Core-сборка (кроссплатформенно, чистый Go)

Работает на Linux, Windows и macOS — нужен только Go-тулчейн:

```bash
# Релизный артефакт: один бинарник с Go-анализатором, роутингом BinZAP,
# режимами vulnscan для сайтов и нативным бэкендом, когда включены теги.
go build -trimpath -ldflags "-s -w" -o analyzer ./pkg/cmd/analyzer
```

Один и тот же артефакт даёт все рантайм-поверхности:

```bash
analyzer --help                 # CLI / сканеры
analyzer --web                 # локальный браузерный UI
analyzer --api --api-port 5000 # REST API (раньше analyzer-api)
```

Встроить метаданные версии для релизной сборки:

```bash
go build -trimpath \
  -ldflags "-s -w -X main.Version=v1.0.0-beta.1 -X main.CommitHash=$(git rev-parse --short HEAD)" \
  -o analyzer ./pkg/cmd/analyzer
```

## Full native сборка (OmniSec + Zig + GNN)

Нативные движки компилируются в библиотеки и линкуются в Go-бинарник через cgo;
анализатор вызывает Rust API напрямую и никогда не запускает отдельный CLI
`omnisec`. Релевантные build-теги — `omnisec_rust_ffi`, `omnisec_ml_gnn` и смежные.

Это выбор на этапе компиляции, а не в рантайме:
- Собери **без** этих тегов (по умолчанию, и именно это лежит в готовых релизах) —
  получишь core-бинарник: чистый Go, без cgo, грузить нечего.
- Собери **с** этими тегами — получишь full-native бинарник, динамически
  слинкованный с Rust/Zig-файлами `.dll` / `.so` / `.dylib`. Такой бинарник
  **требует** наличия этих разделяемых библиотек в рантайме (рядом с
  исполняемым файлом либо в `PATH` / `LD_LIBRARY_PATH`) — если их нет, он не
  запустится. Тихого рантайм-фолбэка между сборками нет; полный разбор
  core vs full-native см. в
  [FAQ.ru.md](FAQ.ru.md#core-vs-full-native--в-чём-разница).

### Windows

```powershell
# Собирает Rust DLL → Zig DLL → линкует Go-бинарник через cgo
.\cicd.ps1 -Stage Build
```

### Linux (через Docker — core-образ)

```bash
docker build -t mega-analyzer .
```

Дефолтный Docker-образ — это лёгкая, полностью статическая **core**-сборка
(CGO выключен), поэтому она работает на любом glibc/musl Linux без
дополнительных рантайм-библиотек.

### Оркестратор CI/CD (Windows)

Скрипт `cicd.ps1` выполняет отдельные стадии релиза:

```powershell
.\cicd.ps1 -Stage Lint      # проверки качества кода
.\cicd.ps1 -Stage Test      # юнит-тесты
.\cicd.ps1 -Stage Package   # полная релизная сборка и упаковка
```

## Тестирование

```bash
# Go-ядро
go test ./pkg/...

# Нативный движок на Rust
cd rust && cargo test --release
```

## Версии тулчейнов

| Компонент | Версия | Нужен для |
| :--- | :--- | :--- |
| Go | 1.27.3+ | Core-анализатор + API-сервер (всегда) |
| Rust | 1.96.1+ | Нативный движок OmniSec (опционально) |
| Zig | 0.17.0+ | SIMD ML-рантайм + песочница (опционально) |
| Elixir / Erlang/OTP | 1.20.0+ / 28+ | Распределённый сервер (опционально) |
