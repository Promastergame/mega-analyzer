# DecisionAI в Mega Analyzer

Исходники движка находятся в каталоге `decisionai/` относительно корня репозитория.
Его Go-модуль называется `decisionai`, версия Go — `1.27.3`.
Mega Analyzer подключается к System One API `/v1/decide`; исходники и готовые
веса остаются в локальном проекте. Импорт второго Go-модуля в анализатор и
скачивание моделей не требуются. Исходники `decisionai/` хранятся в репозитории;
большие локальные веса и сгенерированные файлы исключены из Git.

Проверки на локальных APK не измеряют точность самостоятельного malware-классификатора.
Результаты DecisionAI дополняют свидетельства анализатора. Ограничения и способ
проверки описаны в [оценке качества детектирования](QUALITY_EVALUATION.ru.md).

## Запуск

В PowerShell 7 из корня проекта собрать оба инструмента и запустить сервис:

```powershell
# Выполнять из корня репозитория.
.\scripts\decision-ai.ps1 -Action Build
.\scripts\decision-ai.ps1 -Action Start
.\bin\analyzer-decisionai.exe -t demo/vulnerable-app -report all
```

Помощник запускает скрытый процесс только на `127.0.0.1`, использует готовые
локальные веса, задаёт два рабочих потока и не включает `-escalate`.
Он задаёт `MEGA_DECISION_AI_URL` и `DAI_API_TOKEN` в текущем PowerShell.
Токен не передаётся аргументом командной строки, не печатается и не попадает
в отчёты. Для повторного использования в другом терминале токен хранится
под защитой Windows DPAPI в `decisionai/.runtime/mega-analyzer/`.

Другой терминал может подхватить тот же сервис через `-Action Start`.
Удобный вариант статического сканирования с подключением:

```powershell
Set-Location F:\PROJECTS\mega-analyzer
.\scripts\decision-ai.ps1 -Action Scan -Target 'Button VPN(1).apk' -Output outputs/rat-review
.\scripts\decision-ai.ps1 -Action Status
.\scripts\decision-ai.ps1 -Action Stop
```

Выходные файлы в обычной папке результатов:

- `REPORT.html`: раздел **DecisionAI · Review assistant**, объяснения раскрываются нажатием.
- `analysis.json`: дополнительное поле `decision_ai`.
- `decision_ai.json`: отдельный полный результат дополнительного разбора.
- `DECISION_AI.txt`: читаемая текстовая версия с объяснениями и следующими проверками.

Для Web UI:

```powershell
.\bin\analyzer-decisionai.exe -web -decision-ai-url http://127.0.0.1:7480
```

Использовать режим полного анализа. Настройки передаются дочернему процессу
сканирования; отчёт доступен в обычном просмотрщике результатов. Отдельные
режимы sandbox, decode, Minecraft и REST API пока не используют этот адаптер.

Помощник останавливает только собственный процесс, проверяя путь EXE и время
его запуска. Если порт занят чужим сервисом, он не подменяет его настройки:
можно выбрать другой `-Port` или подключить уже настроенный сервис явно.
Перед пересборкой запущенного `dai.exe` нужно выполнить `-Action Stop`.
Режим `Scan` делает статический анализ: APK не устанавливается, не запускается
и не отправляется во внешние сервисы.

## Параметры

| Параметр | Поведение |
| --- | --- |
| `-decision-ai-url` | Включает разбор находок. Только HTTP(S) на loopback IP или localhost. |
| `MEGA_DECISION_AI_URL` | Адрес по умолчанию из окружения; явный CLI-флаг имеет приоритет. |
| `-decision-ai-url=` | Отключает подключение, в том числе заданное через окружение. |
| `-decision-ai-max-findings 64` | Лимит 1–512 для уязвимостей и malware-индикаторов; сначала максимальная severity. Наблюдения API и защиты остаются в основном отчёте и не расходуют бюджет классификатора. |
| `-decision-ai-budget 30` | Общий бюджет 1–300 секунд; отдельный HTTP-запрос ограничен 5 секундами. |
| `-decision-ai-input file.json` | Отдельный System One запрос без сканирования; результат JSON в stdout. |

Без адреса и без `-decision-ai-input` подключение выключено и запросов нет.
Для отдельного запроса адрес по умолчанию — `http://127.0.0.1:7480`.

Адаптер передаёт сохранённые свидетельства, объяснения и шаги статического
потока. `library` задаётся только когда все известные источники находки
относятся к распознанным пространствам имён SDK; это подсказка по namespace,
а не проверка подлинности библиотеки. Смешанный путь из приложения в SDK
не объявляется библиотечным. `sink` передаётся только из сохранённого пути
source → sink и не означает, что этот путь исполнялся на устройстве.

Для этого подключения DecisionAI полезен как помощник разбора и приоритизации.
Его эксперт `finding-rule` использует свидетельства самого сканера; такой
ответ не является независимым подтверждением. До измерения качества на
размеченных APK оценка `false_positive` не должна автоматически скрывать
находку или менять severity и CI-вердикт.

## Smali и проверка результата патча

```powershell
.\bin\analyzer-decisionai.exe -decision-ai-input examples/decisionai/literal-role.json
.\bin\analyzer-decisionai.exe -decision-ai-input examples/decisionai/patch-effect.json
```

Формат запроса совпадает с System One: `state`, именованные `questions`, типы
`noul`, `choice`, `score`. У вопроса можно указать `task`, `polarity` и
`abstain_key`. Для `choice`/`score` нужны явно перечисленные `criteria`;
порядок критериев сохраняется. Поддержка серверного расширения skill-routing
без criteria в этот адаптер не входит.

`literal-role.json` передаёт реальный фрагмент Smali и номер строки константы;
предсказание роли не доказывает эффект изменения этой константы.
`patch-effect.json` описывает собранный, но ещё не запущенный APK. Успешная
сборка сама по себе не подтверждает эффект патча. Команда ничего не применяет.

## Смысл результатов и ограничения

Автоматический разбор задаёт один вопрос `task=false_positive` на каждую
выбранную находку. Передаёт только уже собранные поля и фрагменты доказательств;
не открывает дополнительные исходники по путям из ответа. Большой контекст
сокращается с явной отметкой `context_truncated` и направляется на ручную проверку.
`state_sha256` связывает ответ с точным JSON-состоянием отправленного запроса.

Поле находки `explanation` также передаётся в пределах лимитов: статус
`observation`, `heuristic`, `static_flow` или `needs_review`, объяснение, сработавшие условия,
ограничения и следующие проверки. В HTML и Markdown они находятся в разделе
**Finding explanations**. У JSON-правил сохраняются реальные вызовы, константы
и декларации, удовлетворившие условиям; тексты предупреждений сканера больше
не используются как признаки из APK. Настроенная уверенность правила не
является измеренной вероятностью вредоносности.

`scanner_rule_advisory` означает, что ответ дал `finding-rule`: это повторная
оценка данных сканера по правилам DecisionAI, а не независимое обнаружение.
`model_advisory` означает другой источник; подробности сохраняются в `source`,
`backend`, `model`, `version`. Оценка `noul` не является измеренной вероятностью
ошибки Mega Analyzer на конкретном приложении.

В дополнительном отчёте разрешены только маршруты `review` и `human`.
Исходная рекомендация сервера сохраняется внутри `response` для аудита.
Ни одна находка не удаляется и не понижается, CI-вердикт и патчи не меняются.
Отказ, отсутствие доказательств или сокращённый контекст требуют человека.

При превышении лимита отчёт имеет статус `partial`. При сбое первой оценки —
`unavailable`; после нескольких успешных — `partial`. Количество пропущенных
находок и ошибка видны в HTML, JSON и тексте. Обычный анализ продолжает работу.

Ответы проверяются на обязательные поля, типы, диапазоны вероятностей,
объявленные варианты и сумму распределения. JSON ограничен по размеру;
HTTP-переадресации и системный proxy отключены. `localhost` преобразуется в
loopback IP. Сервис остаётся отдельно управляемым процессом: анализатор не
запускает его автоматически и не меняет веса.
