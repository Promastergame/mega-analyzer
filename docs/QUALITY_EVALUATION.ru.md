# Оценка качества детектирования

[English](QUALITY_EVALUATION.md)

В репозитории лежит корпус из парных уязвимых и безопасных Android/Smali-фикстур.
Запуск из корня репозитория:

```bash
go run ./cmd/eval -min-precision 1 -min-recall 1 -rule-thresholds testdata/eval/thresholds.json
```

Команда выдаёт машиночитаемые precision, recall и F1 — по каждому правилу
отдельно и микро-усреднённые. На каждое изменение детектора добавляй минимальную
положительную фикстуру и запутывающую безопасную. Изменение схемы корпуса требует
инкремента `version` в `testdata/eval/corpus.json`.

Корпус v5 содержит 97 примеров. На этом наборе precision, recall и F1 равны
1,00: 70 ожидаемых срабатываний категорий, 0 ложных срабатываний и 0 пропусков.
Это регрессионная проверка на фиксированном наборе, а не оценка точности на
произвольных APK.

## Потоки через массивы и вспомогательные методы

23 примера `arrays-*` проверяют полный пайплайн, а дополнительные тесты
`pkg/internal/dataflow/array_flow_test.go` — сам движок:

- `filled-new-array`, `filled-new-array/range`, запись и чтение элементов;
- передачу всего массива в `Runtime.exec` и `ProcessBuilder`, передачу
  массивов в параметры методов и возврат из методов;
- ссылки на один массив через `move-object`, ветвления, недостижимые записи,
  выделение нового массива в том же регистре и безопасную перезапись элемента;
- различение константных индексов и индексов, меняющихся между ветвями;
- данные из `Intent.getStringArrayExtra` и `Bundle.getStringArray`;
- сохранение SQL-экранирования внутри метода и различение экранированной
  и неэкранированной ветвей; значения в параметрах SQL-запроса не становятся
  текстом запроса;
- цепочки вызовов с файлами и строками источника, вспомогательных методов и
  опасного вызова в JSON и сохранённом графе доказательств.

Массивы отслеживаются консервативно по графу управления. Только доказанная
запись в тот же элемент того же массива заменяет предыдущую запись. При
неизвестном индексе или возможных разных объектах сохраняются все возможные
источники. Проверка условий ветвления и произвольных изменений объектов
в сторонних методах в эту модель не входит.

Обход массивов использует общие ограничения на глубину и шаги, а также бюджет
для каждого опасного вызова. Достижение бюджета отражается в
`data_flow_stats.limit_reached` и `slices_truncated`; анализ следующих вызовов
продолжается, пока не исчерпан общий бюджет.
