# Улучшение JAR и Minecraft анализа

Дата: 20 сентября 2026 года.

## Статус результата

Подготовлены изменения исходников, 31 новая регрессионная тестовая функция и один fuzz-target. Два прежних теста скорректированы: они закрепляли ошибочное подавление XXE по наличию строки и высокий риск только за реализацию TLS-интерфейса.

**Сборка, Go-тесты, go vet, race detector и fuzzing здесь НЕ запускались.** В доступном Computer нет Go и gofmt, установка пакетов недоступна. Выполненные лексические проверки исходников не заменяют компиляцию. Изменения нужно проверить в Go-окружении перед использованием в production. Измеренного прироста precision/recall нет, процент точности не заявляется.

Исходный файл `Mega-Analyzer.md` оказался обычным ZIP. Его содержимое распаковано для работы, входной архив переименован в `Mega-Analyzer.zip`. Код из загруженного проекта, Java-классы, установочные и сборочные скрипты не запускались.

## Что делает Minecraft-анализ

Это статический инспектор содержимого, а не запуск Minecraft, антивирус с гарантией безопасности или проверка FPS. Основные реализации: `pkg/minecraft/analyzer.go`, `inspect.go`, `metadata.go`; отдельный CLI: `cmd/minecraft-analyze/main.go`.

Он читает JAR/ZIP/MCPACK/MCADDON и распакованные каталоги. В архивах содержимое обрабатывается в памяти, без извлечения пакета на диск и без выполнения Java, JS или игровых команд. Поддерживаются вложенные архивы с общими лимитами по числу записей, объёму и глубине.

Для Java Edition извлекаются данные Fabric, Quilt, Forge, NeoForge и legacy Forge, а также `pack.mcmeta`: название, идентификатор, версия, авторы, требования Minecraft и зависимости. TOML поддерживается частично. Наличие `data/` помогает отличать datapack от resource pack. Совместимость с вашей установленной сборкой автоматически не доказывается.

Для Bedrock проверяются `manifest.json`, UUID, версии, модули, наличие файла входа скрипта и ссылки на другие упакованные паки. Отсутствующая внешняя зависимость отмечается информационно: она может уже быть установлена в игре. Добавлены проверки зависимости пака от самого себя и некорректных значений версии.

Для `.class` анализируются символические ссылки на методы в constant pool и строковые литералы. Проверки ищут возможности запуска процессов, загрузки нативных библиотек, динамического определения классов, сети и reflection. Новые проверки структуры обнаруживают обрезанные члены и атрибуты класса, повреждённый `Code` и часть неверных ссылок constant pool. Это **не полноценный verifier JVM и не анализ достижимости вызовов**.

Скрипты проверяются по статическим индикаторам: shell, eval, операции с процессами, пути к launcher credentials и Discord webhooks. Такие строки могут находиться в комментариях или неиспользуемом коде. Minecraft-функции отдельно проверяются на административные команды. Файлы ресурсов инвентаризируются: текстуры, модели, звуки и локализации; для PNG/JPEG читаются размеры, для крупных текстур оценивается объём RGBA без mipmaps.

Результат: `analysis.json` и HTML-отчёт. SHA-256 относится к исходному архиву. `complete: false` означает пропуски или неподдержанные части проверки, а не автоматически вредоносность. `risk_score` является суммой категорий индикаторов, ограниченной 100, но не вероятностью заражения.

## Чем общий JAR-анализ отличается от Minecraft-режима

Общий `pkg/internal/jarloader` сканирует Java-архивы, вложенные JAR/WAR/EAR, manifest, классы, секреты в текстовых ресурсах и ограниченный локальный каталог известных уязвимых зависимостей. В основном конвейере результаты передаются через `pkg/internal/apkloader/extractor.go`.

Minecraft-режим использует общий парсер `.class`, но собственные Minecraft-правила. Он не запускает автоматически весь каталог SAST/Maven-проверок общего JAR-анализатора. Поэтому их результаты не следует считать идентичными.

## Что изменено

| Область | Исходная проблема | Изменение |
| --- | --- | --- |
| Структура Java-класса | Парсер заканчивал проверку после интерфейсов и constant pool | Добавлена проверка структуры полей, методов, атрибутов, `Code`, exception tables и конца файла |
| Constant pool | Неверные ссылки могли превращаться в пустые значения без ошибки | Проверяются типы и границы ссылок, резервный слот long/double, method handles и method types |
| Строковые литералы | Пустой список литералов оставался `nil`, что включало fallback на имена/дескрипторы | Различаются пустой разрешённый список литералов и вручную созданный ClassFile; Minecraft использует cpString |
| Unicode JVM | Суррогатная пара modified UTF-8 не объединялась в один символ | Добавлено декодирование через UTF-16 с сохранением ASCII fast path |
| ZIP64 / бюджеты | Приведение размера и сложение могли приводить к неверному учёту; вложенный архив учитывался дважды | Проверка до сложения, отрицательные значения отклоняются, повторное списание контейнера убрано |
| Обрезанное чтение | `LimitReader(limit)` мог вернуть начало файла без признака превышения | Проверка declared size, чтение до `limit+1`, проверка полного размера и CRC для читаемых записей |
| Повреждённые вложения | Ошибки открывания и чтения могли теряться | Новые `complete` и `inspection_issues`, предупреждения в основном конвейере |
| Дубликаты nested JAR | Поиск по имени каждый раз выбирал первую запись | Каждая ZIP-запись передаётся отдельно; дубликаты явно отмечаются |
| Пути и special files | Общий JAR-обход не отсекал часть неоднозначных записей | Добавлены проверки опасных путей и non-regular ZIP entries |
| Производительность | Insertion sort и повторный поиск вложений давали квадратичную работу | Стандартная сортировка и прямые ссылки на ZIP-записи; ускорение не бенчмаркалось |
| XXE | Любая строка XML hardening полностью скрывала предупреждение | Предупреждение сохраняется: строка не доказывает значение аргумента и защищённость конкретного parser instance |
| TLS | Сам факт реализации trust manager трактовался как high-risk | Без анализа тела метода это low-severity review point, а не доказанный trust-all |
| Java API | Сопоставление владельца метода по суффиксу давало ложные совпадения | Точное имя класса; отчёт явно говорит constant-pool reference и `execution_proven=false` |
| Crypto | Отчёт изображал конкретный вызов Cipher.getInstance с найденной строкой | Формулировка заменена на совместное присутствие ссылки и литерала; поток аргумента не выдумывается |
| Maven | Одинаковый artifactId другого groupId мог получить чужой CVE | Проверка известных groupId; при отсутствующем groupId только информационный кандидат |
| Числа версий | Ошибки strconv.Atoi игнорировались | Переполнение означает нераспознанную версию |
| Minecraft ZIP | Вложение с расширением `.bin` не анализировалось как архив | ZIP определяется также по сигнатуре, с прежними лимитами и исправлением счётчиков ресурсов |
| Minecraft команды | `say run op Alice` мог считаться выполнением op | Проверяются позиции команды и `execute ... run`, учитываются кавычки, selector/NBT delimiters и namespace `minecraft:` |
| Minecraft API | Часть современных способов сети и загрузки классов не учитывалась | Добавлены HttpClient.send/sendAsync, Lookup.defineClass/defineHiddenClass и Runtime.load/loadLibrary |
| Версии Bedrock / pack format | JSON `null` мог превращаться в ноль | `null` не принимается вместо числа; уточнены зависимости и пути входа скрипта |
| Полнота Quilt | Compound dependency не разрешалась, но отчёт оставался complete | Неподдержанная зависимость теперь отмечает неполную проверку |
| Индекс сигналов | Первое слабое совпадение категории могло скрыть более сильное | Учитывается максимальная severity каждой категории, независимо от порядка |

Полный перечень изменения строк находится в приложенном patch. Для проверенных поддерживаемых записей сохраняется принцип «анализировать без запуска».

## Проверки и запуск

Проект требует версию Go, указанную в `go.mod` (в исходном архиве: `go 1.27.1`). Этот файл и базовая версия проекта не изменялись. Не нужно применять исправления только к уже собранному EXE: исходники необходимо пересобрать.

Из корня проекта:

````bash
bash scripts/validate-jar-minecraft.sh
RACE=1 FUZZ=1 INTEGRATION=1 bash scripts/validate-jar-minecraft.sh

go build -o minecraft-analyze ./cmd/minecraft-analyze
./minecraft-analyze -path mod.jar -output analysis_output/minecraft
./minecraft-analyze -path addon.mcaddon -json
````

На Windows тесты можно запустить напрямую:

````powershell
go test -count=1 ./pkg/internal/jarloader ./pkg/minecraft ./cmd/minecraft-analyze
go vet ./pkg/internal/jarloader ./pkg/minecraft ./cmd/minecraft-analyze
go build -o minecraft-analyze.exe ./cmd/minecraft-analyze
.\minecraft-analyze.exe -path "C:\Downloads\mod.jar" -output analysis_output/minecraft
````

`-race` требует поддерживаемой платформы и C toolchain. Интеграционные тесты основного приложения могут потребовать дополнительные компоненты проекта. Перед слиянием изменений выполните также `gofmt` для изменённых Go-файлов. Приложенный скрипт не устанавливает зависимости и не запускает код сканируемого мода.

## Что действительно проверено здесь

Проверено распознавание ZIP и безопасное извлечение исходников, просмотрены изменения, выполнены проверки сбалансированности лексических разделителей и использования импортов для 13 изменённых/новых Go-файлов. Проверены уникальность обычных функций в затронутых пакетах, отсутствие ошибок whitespace с учётом CRLF и синтаксис нового shell-скрипта через `bash -n`.

`source-checks.json` сохраняет результат этих ограниченных проверок. Он не является логом `go test`. Архив результата дополнительно проверен по CRC и сопоставлен с исходником по списку изменённых и добавленных файлов. Компиляция и реальные результаты тестов остаются открытым этапом.

## Следующий этап для действительно более сильного анализатора

**Приоритет 1: инструкции и источники данных.** Разбирать bytecode `Code`, сохранять реальные invoke-инструкции с методом и смещением, разрешать BootstrapMethods/invokedynamic и строить ограниченный граф вызовов. Отдельно отмечать уровни доказательства: текст, constant-pool reference, инструкция, достижимость, поток данных. Сам факт invoke-инструкции тоже не доказывает выполнение.

**Приоритет 2: контекст Minecraft.** Добавить анализ Fabric/Quilt entrypoints, Forge/NeoForge событий и mixins, обнаружение registration callbacks; строить пути от известных точек входа к file/network/process API. Чтение launcher credentials вместе с сетевым API должно считаться co-occurrence, пока не доказан поток данных между ними.

**Приоритет 3: зависимости и совместимость.** Полноценный TOML, граф версий Fabric/Quilt/Forge и модульных Bedrock-зависимостей, циклы, предоставляемые alias ID и optional зависимости. Для Multi-Release JAR выбирать классы под заданную Java, а не только максимальный class major. Отдельно поддержать plugin.yml/paper-plugin.yml и не смешивать серверные плагины с обычными модами.

**Приоритет 4: подтверждение CVE и происхождения.** Обновляемая база advisories с точным GAV/PURL и ветками исправлений, учётом prerelease/backport, происхождением и датой данных. Текущие правила CVE ограничены и в этом изменении не актуализированы. Имя JAR само по себе всё ещё является эвристикой. Подпись JAR не равна доверию к издателю; проверку подписи и trust policy нужно реализовывать отдельно.

**Приоритет 5: измерение качества.** Размеченный корпус легитимных модов и вредоносных/повреждённых образцов; разделение библиотек и авторского кода; precision/recall по каждому правилу; golden reports, fuzzing архивов/классов/metadata и лимиты CPU/RAM. До такой оценки обещание «точность 99%» было бы необоснованным.

## Оставшиеся ограничения

Скриптовые regex могут срабатывать на комментарии, alias-вызовы и обфускация могут скрывать поведение. Новый разбор Minecraft-команд является ограниченным лексером, а не полной грамматикой всех версий, macro-функций и расширений серверов. Advanced TOML, полная версия/совместимость, stubs и malformed MUTF-8, dataflow, настоящий trust-all по телам методов, native payload execution и поведенческий анализ не решены этим изменением. Общий JAR-сканер проверяет CRC читаемых поддерживаемых записей, а не гарантирует полную валидацию каждого ресурса архива. Неполнота должна учитываться пользователем при интерпретации результатов.

**Это целевой набор исправлений JAR/Minecraft, а не заявление, что во всём Mega-Analyzer устранены все ошибки.**
