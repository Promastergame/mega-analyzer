# Проверка источников и охват GNN

При обычном запуске с `-decision-ai-url http://127.0.0.1:7480` анализатор
сохраняет `SOURCE_EVIDENCE.json` и `SOURCE_EVIDENCE.txt`, затем передаёт
DecisionAI типизированные статические проверки вместе с полными источниками,
на которые они ссылаются.

Проверяются:

- вызовы `System.load` / `System.loadLibrary` в сохранённом CFG;
- происхождение аргумента загрузки в сохранённых вызовах;
- имя в аргументе `FileOutputStream`, включая `File` и строковые построители;
- явное значение `android:usesCleartextTraffic` в `application`;
- объявления компонентов, `exported` и защитные разрешения.

Проверки потока повторно используют CFG и reaching definitions анализатора.
Перезапись регистра прекращает прежнюю цепочку. Разные ветви сохраняются как
альтернативы. Прямые вызовы разрешаются по полной сигнатуре; параметры
возвращаемых значений привязываются к конкретному вызову. Неизвестные функции,
неполный CFG, конфликтующие определения и неучтённые изменения объекта через
другой регистр оставляют проверку неопределённой. Размеры кода, количество
источников и шагов ограничены.

`source-evidence-rule` проверяет SHA-256, позиции и текст цитат, затем
показывает статическую оценку сканера. Анализ потока выполняет сканер.
Маршрут остаётся `review` или `human`; это не независимое подтверждение.
Противоречащий ответ сохраняется в отчёте и направляется на ручную проверку.
Находки, severity, оценки риска и CI-вердикт эти проверки не меняют.

SHA-256 источника относится к сохранённому представлению метода или
декодированного манифеста. Хеш исходного APK остаётся отдельным полем.

DecisionAI 1.19 добавляет отдельную задачу `smali_literal_role_neural`.
Она передаёт обученной R-GCN граф использования выбранной числовой константы
в одном сохранённом методе. Во вход не входят находки сканера, их severity
или подготовленные выводы. Результат — распределение ролей: маска, флаг,
цвет, задержка, лимит, индекс/размер и другие классы smalirole.
LR и голоса правил в этот результат не подмешиваются.

В `decision_ai.json` поле `code_review` сохраняет локальную строку метода,
строку представления файла, хеш исходного текста, хеш весов, размер графа,
число нейронных проходов и полный ответ. Пропуски и ошибки остаются отдельными
результатами. Неиспользуемые/перезаписанные значения, недостижимые инструкции
в сохранённом обычном CFG, неполный ввод, float-параметры и значения,
используемые как ссылки на объекты или массивы, не получают
нейронный прогноз. Оценка ниже 0.8 остаётся неуверенной рекомендацией.
Нет нужной GNN — задача сообщает недоступность, без замены текстовой моделью.
При пропуске или недоступности модели поля `choice`, `probabilities` и
`confidence` отсутствуют.

Модель обучалась на слабых метках из типизированных мест использования
констант в APK. Это ограниченная оценка назначения значения, а не модель
вредоносного поведения, доказательство выполнения или генератор объяснений.
Текст карточек формируют шаблоны отчёта. Правила подготовки графа и проверки
охвата сами по себе не являются нейронными предсказаниями.

HTML размещает связанные ответы внутри карточек находок. Связь требует
идентичности находки либо точного файла и метода; одного имени файла или
заголовка недостаточно. Проверки без подходящей карточки доступны по ссылкам
в свёрнутой строке охвата. Неоднозначные перегрузки методов не объединяются.

Статический путь не устанавливает выполнение. Явная политика cleartext не
показывает, что был HTTP-запрос; при Network Security Config следует проверить
его правила. Объявление компонента не подтверждает наличие его реализации
или возможность обойти защитное разрешение.

`GNN_DIAGNOSTICS.json` содержит модель, её SHA-256, классы, общие счётчики
охвата, предсказания, quality gate и причины пропуска методов. Детальные
записи ограничены; число записей, не сохранённых из-за лимита, указано отдельно.
Для больших отчётов HTML показывает первые 100 записей.

Автопоиск выбирает `gnn_weights.json` из `~/.analyzer/models` или расположения
рядом с установленным анализатором, включая каталог `rust` проекта.
`-gnn-model` имеет приоритет. Формат `.gnnbuf` поддерживает нативный загрузчик,
но текущий контракт проверки Go принимает JSON: экспортируйте JSON для
проверенного запуска. Компактный файл больше не перекрывает совместимый JSON.

Классы GNN описывают лицензирование, перепаковку и защитные механизмы.
`benign` означает отрицательный класс этой таксономии для видимого метода.
Скрытый DEX, нативный payload и семейство вредоносной программы такая метка
не разрешает. Метаданные точности на обучающем наборе не измеряют точность
на произвольном APK.

В объяснениях находок HTML и Markdown бинарные свидетельства показываются как hex-превью первых
256 байтов. Это сохраняет корректный UTF-8 в текстовом отчёте. Полные байты
следует смотреть в исходном артефакте; объекты находок и их дайджесты при
построении представления не изменяются. Длинные текстовые подписи обрезаются
по границе символа UTF-8.
