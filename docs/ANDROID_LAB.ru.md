# Локальный Android для сандбокса

`scripts/android-lab.ps1` создаёт отдельный AVD, запускает его, проверяет готовность
Android и прогоняет модули анти-VM. Диски и журналы лежат в `.tmp/android-lab/`.
AVD регистрируется в стандартном каталоге пользователя, поэтому его видит селектор
окружений в веб-интерфейсе. По умолчанию используется Android 15, API 35, x86_64.
Если SDK не знает профиль экрана Pixel 8, выбирается доступный Pixel; версия
образа Android при этом остаётся API 35.

Из корня проекта:

```powershell
./scripts/android-lab.ps1 -Action Setup
./scripts/android-lab.ps1 -Action Start
./scripts/android-lab.ps1 -Action AntiVM
./scripts/android-lab.ps1 -Action Stop
```

Если Happ работает как локальный HTTP-прокси, укажи его SDK Manager явно:

```powershell
./scripts/android-lab.ps1 -Action Setup -HttpProxy http://127.0.0.1:10809
```

Порт `10809` нужно брать из своего запущенного Happ: он может отличаться.
Скрипт не меняет системный прокси Windows. Для Java включается IPv4 только на
время выполнения; прежние переменные окружения затем восстанавливаются.

Уже скачанный официальный архив API 35 revision 9 можно установить через
`-ImageArchive <путь>`. Перед распаковкой проверяются размер и SHA-1 из
официального каталога Google, затем пути внутри ZIP. Незавершённый архив не
устанавливается, существующая папка образа не перезаписывается.

Эмулятор по умолчанию запускается без окна, на `emulator-5570`, с 2 CPU и 2 ГБ RAM.
`-ShowWindow` открывает его окно. `-Port 5572` позволяет выбрать другой чётный порт.
Для установленного старого образа Android 9 есть `-ApiLevel 28`.
Android 7.0 и 7.1 соответствуют `-ApiLevel 24` и `25`; эти параметры требуют
соответствующего установленного образа. API 28 — Android 9.
`-AvdName <имя>` позволяет выбрать существующий AVD. Для диагностики доступны
`-GpuMode off` и `-Acceleration off`; эти режимы не гарантируют загрузку Android.
Перед работой с устройством скрипт проверяет точное имя AVD: другой телефон или
эмулятор на том же порту не будет выбран.

Используется `-read-only` с временным диском изменений, без загрузки и сохранения
Quick Boot. После остановки изменения приложения не становятся базовым состоянием
AVD. Готовность проверяется по завершению загрузки, остановке boot animation и
работающему package manager.

## Подмена модели и имени устройства

Для подмены используется выдуманная модель **PromasterPhone 1**, бренд
`promaster`, производитель `Promaster`, device/product `promasterphone1`.
Профили `promasterphone-1-avd-api-28.json` и `promasterphone-1-avd-api-35.json`
содержат согласованные fingerprint, build ID, hardware и board. Версия Android
и ABI соответствуют установленному образу.

На доступном Android 9:

```powershell
./scripts/android-lab.ps1 -Action Start -ApiLevel 28 -Port 5572 -MaskIdentity
```

На уже запущенном AVD:

```powershell
./scripts/android-lab.ps1 -Action Identity -ApiLevel 28 -Port 5572
```

Номер виртуальной SIM задаётся при запуске через `-PhoneNumber`. Можно передать
цифры или формат с `+`, пробелами, скобками и дефисами; эмулятор получает только
цифры, максимум 15. Для выбранного тестового номера:

```powershell
./scripts/android-lab.ps1 -Action Start -ApiLevel 28 -Port 5572 `
  -Restart -PhoneNumber '+1 202 555 0123' -MaskIdentity
```

`-Restart` завершает только проверенный лабораторный AVD и запускает его заново.
Временный диск сбрасывается, scrcpy на время отключается. Без `-Restart`
изменение номера на уже запущенном AVD возвращает ошибку до применения профиля.
Без `-PhoneNumber` эмулятор использует свой стандартный номер, связанный с портом.
С `-MaskIdentity` проверяется номер, прочитанный через `TelephonyManager` в APK.
Разрешения `READ_PHONE_STATE`/`READ_PHONE_NUMBERS` выдаются только нашему пробнику;
возможность чтения этих данных другим APK зависит от его разрешений и версии Android.

Скрипт получает root через `adb root`, собирает и устанавливает локальный
помощник записи свойств и тестовый APK, применяет `identity`, `environment`,
`battery`, `display`, затем задаёт `Settings.Global.device_name`. Проверка читает
`Build.MODEL`, производителя, device/product, hardware/board, fingerprint,
build ID, security patch и имя устройства из обычного приложения. Каждый
запуск имеет новый `capture_id`; старый файл не может подтвердить успех.
Результаты находятся в `.tmp/android-lab/identity-<дата>/`: `app-before.json`,
`app-after.json`, `app-verification.json`, `result.json`, `diff.json` и сессия.
Пробник также записывает номер SIM, значение `Settings.Global.ADB_ENABLED`
и доступный sticky broadcast `USB_STATE`. Если USB-состояния нет, поля
`usb_connected`/`usb_configured`/`usb_adb` записываются как `null`, а не `false`.

Другой профиль можно выбрать через `-ProfilePath <путь>`. Готовые профили подмены
рассчитаны на API 28/35. Android 7 в текущем SDK отсутствует; работоспособность Android 15
на этом хосте пока не подтверждена из-за сбоев загрузки эмулятора.

Помощник меняет существующие `ro.*` в памяти на root AVD. После записи
перезапускается zygote, поскольку новые процессы иначе наследуют старые
`Build.*`; скрипт ждёт новый system_server, package manager, оконную систему
и разблокировку пользователя 0. Для старого EGL с host GPU перед отключением
`ro.kernel.qemu` создаётся временный bind mount с согласованными алиасами
графических библиотек. Селекторы HAL сохраняют рабочие реализации эмулятора.
Содержимое системных образов не редактируется; при остановке AVD временные
подмены исчезают. Ошибка итоговой проверки оставляет загруженный AVD для осмотра.

Подмена основных свойств убирает простые проверки SDK-модели и QEMU-флагов.
Файлы QEMU/goldfish, селекторы HAL, свойства драйверов и x86_64 остаются видимыми.
Поэтому успешное совпадение профиля не означает полное скрытие виртуальной машины.

Другие сигналы для анализа: оставшиеся build/boot-свойства и серийные номера,
ABI/CPU и строки графического драйвера, устройства QEMU/goldfish, состав и
динамика сенсоров, SIM/IMEI/оператор, root/отладчик/ADB, набор приложений и
пользовательских данных, а также несогласованность этих признаков между собой.
Доступность отдельных проверок зависит от разрешений и версии Android.
ADB — самостоятельный признак анализа даже при неизвестном USB-состоянии;
его наличие встречается и на физических устройствах. scrcpy использует ADB.

## Проверка анти-VM

Проверяются `identity`, `environment`, `battery` и `display` отдельно. Это позволяет увидеть
результат батареи даже при критическом отказе изменения идентификаторов.
Каждый прогон сохраняет `before.json`, `after.json`, отчёт проверки и `diff.json`;
папка прогона печатается в терминале.
`display` задаёт размер и плотность через `wm` и проверяет действующие значения
с учётом override. Батарея задаёт и проверяет уровень, статус (включая
`not-charging`), температуру, здоровье и источник питания.

Для одного прогона всех модулей без остановки после первого критического отказа:

```powershell
./.tmp/android-lab/antivm.exe session start --profile ./pkg/internal/antivm/profiles/promasterphone-1-avd-api-35.json `
  --serial emulator-5570 --continue-on-failure --report json --sessions ./.tmp/android-lab/sessions
```

Критический отказ сохраняет итоговый `failed` и ненулевой код выхода.
`--strict` останавливает прогон при первой ошибке даже с `--continue-on-failure`.
Каждая ADB-команда ограничена 15 секундами, вся сессия — `--timeout` (по умолчанию
3 минуты). Перед изменениями проверяются соединение и загрузка Android.

По умолчанию выбирается профиль PromasterPhone 1 для API выбранного AVD.
Подмена модели не обновляет Android и не превращает x86_64 в ARM64.
Проверка `identity` сравнивает также Android release, API и ABI с профилем:
несовпадение остаётся ошибкой даже при совпавшей модели и fingerprint.

`-Action AntiVM` использует обычный `setprop`, который не может менять уже
установленные свойства `ro.*`. Поэтому
`identity` и `environment` на стандартном образе могут завершаться с `failed`;
отчёт сохраняет настоящий ответ Android и значения, прочитанные после операции.
Для реальной подмены используй `-Action Identity` или `Start -MaskIdentity`;
в CLI помощник выбирается через `--resetprop <путь в Android>` вместе с
`--restart-framework`.
Батарея проверяется через `dumpsys battery`. Наличие корректного профиля и
успешная подмена батареи сами по себе не подтверждают скрытие виртуальной машины.
Снимки состояния включают наличие устройств QEMU/goldfish. `session diff` учитывает
включённые `ro.kernel.qemu` и `ro.boot.qemu`; отсутствующий файл или выключенный флаг
не считается найденным признаком VM. Оценка остаётся эвристикой, а не вероятностью
обнаружения эмулятора приложением.

`session verify --replay <after.json>` только читает сохранённое состояние;
операции подмены не выполняются. Отчёт содержит `verify_only: true`.
Опечатка или неподдерживаемое имя в `--module` возвращает ошибку использования
до создания сессии.

Логи загрузки разделены по имени AVD и порту (`<имя>-<порт>.stdout.log` и
`.stderr.log`). При неудачной загрузке скрипт завершает также дочерний процесс QEMU,
если Windows разрешает его перечисление.

## Запуск APK

После запуска AVD:

```powershell
go build -o ./.tmp/android-lab/analyzer.exe ./pkg/cmd/analyzer
./.tmp/android-lab/analyzer.exe -android-sandbox -sandbox-device emulator-5570 `
  -t ./app.apk -sandbox-duration 30 -sandbox-allow-net `
  -sandbox-uninstall-after -sandbox-output ./.tmp/android-lab/reports
```

Для Android ещё нет механизма блокировки сети. Запрос без явного
`-sandbox-allow-net` останавливается на этапе preflight до установки APK.
Раньше этот путь включал Wi-Fi и мобильные данные даже при запросе блокировки.

Java-аварии приложения из `logcat` добавляются в предупреждения, описание поведения
и журнал активности. Запись должна содержать `FATAL EXCEPTION` и совпадающие имя
пакета и PID; ошибки других приложений не приписываются образцу. Наблюдение
продолжается до остановки или заданного срока. Завершение по сроку записывается
как `duration_elapsed`, ручная остановка — как `stopped`.
