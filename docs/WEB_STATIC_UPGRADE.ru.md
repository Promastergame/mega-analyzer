# Обновление веб-конвейера статического анализа

## Что изменено

- **Full Static Analysis** принимает APK/DEX/архивы и отдельные `.bundle`, `.hbc`, `.jsbundle`, `.js`, `.mjs`, `.cjs`.
- Отдельные пункты **JS Deobfuscate** и **JS Patch** убраны из веб-навигации. Старые `/js` и `/js-patch` открывают Full Static Analysis. CLI-команды и старые API-режимы оставлены для совместимости.
- В результатах есть список файлов, скачивание отдельных файлов и **Download all files as ZIP**. Он доступен и для Decode, и для старых JS-заданий, даже если `analysis.json` отсутствует. Ошибка/неполнота не скрывается за сообщением «всё готово».
- Результаты находятся внутри постоянной папки задания, а не рядом с временным загруженным файлом. Очистка загрузки их не удаляет.
- Декомпиляцию APK/DEX можно включить одновременно с анализом: отдельная папка `decoded/` содержит Smali и декодированные ресурсы. IR остаётся внутренним форматом сканера, а не единственным доступным результатом.
- Добавлен отсутствовавший метод не-Windows-заглушки, из-за которого исходный архив не собирался на Linux. Исправлено ложное `Interrupted` при штатном завершении контекста.

## Как запустить

Требуется Go **1.27.1** — это версия из исходного `go.mod`; она не менялась.

Linux/macOS:

```sh
go build -o analyzer ./pkg/cmd/analyzer
./analyzer -web
```

Windows PowerShell:

```powershell
go build -o analyzer.exe ./pkg/cmd/analyzer
.\analyzer.exe -web
```

Открой адрес, напечатанный сервером. По умолчанию это `http://127.0.0.1:7474/`.
Новый интерфейс встроен в бинарник: необходимо **пересобрать и перезапустить** сервер, а не только заменить HTML рядом со старым исполняемым файлом.

## Настройки в Full Static Analysis

Открой **Modules & output / Модули и вывод**.

| Настройка | CLI-флаг | Результат |
| --- | --- | --- |
| Hermes export budget | `-bundle-budget large` / `compact` | Ограниченный бюджет функций/инструкций/размера вывода. |
| Export bundle code / disassembly | `-bundle-export` | Веб-переключатель включён по умолчанию; CLI-флаг — явно. Текстовый JS деобфусцируется, Hermes дизассемблируется. |
| JS patch candidates (dry-run) | `-bundle-patches` | Markdown и JSON с кандидатами, без изменения входного файла. Hermes — только сканирование. |
| Save decoded APK / DEX | `-save-decoded` | Smali и ресурсы в `decoded/` рядом с отчётами. Для APK/DEX/поддерживаемых архивов. |
| Java pseudocode view | `-java-view` | Псевдокод Java рядом со Smali; требует включённого сохранения декодированного APK. Это не исходный Java. |
| Skip resource decoding | `-no-resources` | Не декодировать ресурсы в дополнительной папке `decoded/`; не отключает анализ ресурсов сканером. |
| Copy original APK metadata | `-copy-original` | Сохранить исходные META-INF и прочие поддерживаемые файлы в декодированном выводе. |

Зависимые настройки в веб-форме отключены, пока не включён Save decoded. Для отдельного JS/HBC-файла декодирование APK отключено. CLI позволяет дополнительно использовать существующий `-standalone`, `-dex-backend`, `-no-smali` и параметры нативной сборки Smali; произвольные пути к внешним инструментам из веб-формы не принимаются.

### APK + бандлы + декодированные файлы

```sh
./analyzer -t app.apk -output result -no-tui -bundle-export -bundle-patches -save-decoded -java-view
```

### Отдельный Hermes / JS-бандл

```sh
./analyzer -t index.android.bundle -output result -no-tui -bundle-export -bundle-patches
```

### Только декодирование APK, без анализа

Существующий режим Decode / unpack сохранён; теперь его файлы также можно скачать в экране результатов.

```sh
./analyzer -decode -t app.apk -o decoded_app -no-tui
```

## Какие файлы появятся

```text
result/
  REPORT.html
  REPORT.md
  analysis.json
  static_outputs.json
  decoded/                         # при -save-decoded
    AndroidManifest.xml            # для APK; зависит от входа/флагов
    smali/                         # при наличии DEX и без -no-smali
    ...
  bundles/
    assets/index.android.bundle.export/
      coverage.json
      original.bundle
      hermes.json                  # для распознанного поддерживаемого HBC
      hermes.disasm.txt            # для распознанного поддерживаемого HBC
      # либо deobfuscated.js для текстового JS, не для HBC
  bundle_patches/
    assets/index.android.bundle.report/
      JSPATCH.md
      jspatch.json
```

Пути отражают расположение бандла во входном дереве. Для отдельного файла промежуточная `assets/` обычно отсутствует. При ошибке/неподдерживаемом формате часть файлов может отсутствовать: смотри `static_outputs.json`, `coverage.json` и логи. Файлы дополнительного декодирования сохраняются даже при частичном результате; реальная ошибка декодирования даёт ненулевой код завершения после сохранения отчётов анализа.

## Важно про Hermes 96

В проекте уже были нативный парсер и таблица опкодов **v96**. Теперь они используются для выгрузки читаемого дизассемблирования, функций, строк и метаданных вместо попытки обработать бинарный HBC текстовым JS-деобфускатором.

**Это не восстановление исходного JavaScript.** Новый код не реализует высокоуровневый Hermes→JS-декомпилятор, обратную компиляцию HBC или генерацию пропатченного APK. Для Hermes патчер по-прежнему работает только в режиме анализа; это явно указано в результатах. Для текстового JS создаётся `deobfuscated.js`; преобразования не гарантируют полное снятие любой обфускации.

Неподдерживаемая версия, повреждённый заголовок, неизвестная инструкция или достижение бюджета не маскируются под полный результат. Исходный бандл сохраняется, статусы показывают `unsupported`, `failed` или `partial`. Unity AssetBundle не переписывается как JavaScript.

Ограничения: исходный бандл до 128 MiB. Новый флаг `-bundle-budget large|compact` выбирает ограниченный бюджет, по умолчанию `large`:

| Бюджет | Функции | Байткод | Инструкции экспорта | Текст дизассемблирования | Сохранённые места вызова в графе |
| --- | ---: | ---: | ---: | ---: | ---: |
| `large` | 100 000 | 64 MiB | 10 000 000 | 512 MiB | 250 000 |
| `compact` | 5 000 | 16 MiB | 1 000 000 | 64 MiB | 2 000 |

Лимиты экспорта и графа учитываются отдельно. При достижении любого лимита статус становится `partial`; причина и фактические счётчики доступны в `coverage.json`, `static_outputs.json`, `analysis.json`, веб-интерфейсе и отчётах. Полные строки остаются в `hermes.json`, в дизассемблировании они ограничены превью по 256 байт. Потоковая запись метаданных уменьшает пиковые выделения памяти. Неполные стадии отмечают весь запуск как `incomplete` в `run.status`; `scan_only` для Hermes означает отсутствие патчинга, а не ошибку.

Список веб-файлов показывает первые 2000 записей с явным предупреждением; ZIP содержит все обычные файлы до 200 000 записей. За этим пределом сервер отказывает в архиве, не обрезает его молча. Символические ссылки не включаются в ZIP; чтение файлов ограничено папкой результата через `os.Root`.

## Проверки этой версии

- `go test ./pkg/internal/apkloader ./pkg/cmd/analyzer/web ./pkg/cmd/analyzer -count=1`
- `go vet ./pkg/cmd/analyzer/web ./pkg/internal/apkloader ./pkg/cmd/analyzer`
- Сборка `./pkg/cmd/analyzer` на Linux.
- Регрессионные тесты Hermes 96, текстового JS, повреждённого HBC, неизвестной версии, Unity, отмены, сохранения Smali/Java-псевдокода, кандидатов патчей, сохранности оригинала, скачивания ZIP и защиты от выхода из папки через путь/символическую ссылку.
- Локальная браузерная проверка: загрузка синтетического HBC v96 и тестового APK с HBC внутри, получение файлов/ZIP, наличие Smali/Java-псевдокода, отсутствие отдельных JS-инструментов и JS-ошибок в браузере. Скачанные ZIP прошли проверку целостности.

## Дополнение Bundle fix 2 — проверено на присланном результате

Из ZIP результата взят сохранённый `original.bundle` (20 015 460 байт, HBC v96). Сам APK в этой проверке не использовался; это не проверка безопасности приложения целиком.

- Строки: 189 236 / 189 236.
- Дизассемблирование: 62 022 / 62 022 функций; 1 758 796 инструкций; 7 195 336 / 7 195 336 байт кода.
- Граф: 62 022 / 62 022 функций; записано 182 963 / 182 963 мест вызова. Неразрешённые косвенные вызовы остаются неразрешёнными, полного runtime call graph не обещаем.
- Вывод дизассемблирования: 118 647 776 байт. В `large` выбранные бюджеты не достигнуты; экспорт `complete`, кандидаты патчей `scan_only`.
- В `compact` воспроизведено честное `partial`: 5000 / 62 022 функций; ограничение сохранённых вызовов 2000. Метаданные строк и заголовков не обрезаются этим лимитом.
- Устранён двойной подсчёт typed/legacy представлений: 128 записей вместо 256. Различные payload одной bridge-записи не склеиваются.
- URL, документация, bridge-имена и семантические строковые признаки — информационный inventory, не доказанные уязвимости. Независимые детекторы секретов сохраняют свою оценку.
- В отдельном бандле CLI/HTML/Markdown/веб показывают `NOT ASSESSED`, а не `LOW RISK` по пустым Smali-счётчикам. Счётчики бандла отделены от DEX/Smali. Время включает подготовку/скан/экспорт, время core pipeline указано отдельно.
- В `analysis.json` добавлены `bundle_analysis` и `static_outputs`. SHA256 привязан к исходному файлу, не к временной папке.
- Профиль бюджета входит в ключ кеша JSPatcher; `compact` и `large` не используют один отчёт.

Проверены тесты и `go vet` шести изменённых пакетов: apkloader, jspatcher, pipeline, report, web и cmd/analyzer. Пройдены 15 браузерных проверок: реальный бандл через загрузку веб-формы, измеряемое покрытие, счётчик 128 INFO, скачивание coverage.json, отсутствие LOW RISK, сохранение русского языка после перезагрузки, отсутствие отдельных JS-пунктов и ошибок JS. Дополнительно проверено сохранение Smali/Java-псевдокода на тестовом APK.

Собрана стандартная Windows amd64 версия (`CGO_ENABLED=0`) и проверен формат исполняемого файла; запуск на Windows здесь не выполнялся. Это не сборка с `omnisec_ml_gnn`: прежнее предупреждение о наличии весов без GNN остаётся корректным. Android/Windows-приложение из вложения не запускалось.

Для отличимой сборки:

```powershell
go build -ldflags "-X main.Version=1.0.0-beta.4-bundlefix2 -X main.BuildDate=2026-10-16" -o analyzer.exe ./pkg/cmd/analyzer
.\analyzer.exe -web -web-port 7475
```

В готовом Windows ZIP есть `START-WEB.cmd`; перед запуском закрой старый сервер штатно (Ctrl+C в его консоли). Не запускай одновременно старый и новый exe на одном порту. Внизу новой веб-страницы есть отметка `Bundle fix 2`. Переключатель RU/EN и выбранный язык сохранены. Если открыта вкладка с кешированной страницей, перезагрузи её после остановки старого сервера и запуска нового.
