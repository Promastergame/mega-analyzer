# Mega Analyzer: снижение ложных срабатываний

## Что изменено

- Сопоставление условий правил по умолчанию учитывает границы идентификаторов: `su` не совпадает с `usually`, а `Socket` — с `DefaultTrustedSocketFactory`. Для намеренного поиска подстроки доступен явный `"match_mode": "substring"`; совпадение и свидетельство используют одинаковую семантику.
- Подозрительное ключевое слово само по себе не становится критическим. Исправлена передача шаблона в precision gate; опасные разрешения и большинство экспортированных компонентов не объявляются критическими только из-за наличия, но остаются в отчёте.
- Признаки пиратства отделены от классификации malware. `keygen`, `xmanager` и `microg` не ищутся внутри произвольных длинных идентификаторов; одиночное слово `keygen` не критично (это также элемент HTML). Неоднозначное `isRegistered` убрано из признаков лицензии; endpoint аутентификации сам по себе не критичен.
- Общие комбинации HTTP+JSON, сокеты с потоками, наличие SSL API не объявляются доказательством C2, RAT или обхода pinning: они оставлены как низкоуверенные наблюдения. Это снижает ложные срабатывания, но может снизить обнаружение угроз без дополнительных признаков.
- При дублировании file-scoped правил приоритет у кода приложения. Найденное только в распознанной библиотеке сохраняется, но уровень/уверенность снижаются и добавляется оговорка: имя библиотеки не доказывает безопасность или недостижимость кода. Счётчик библиотек исправлен и помечен как число распознанных единиц.
- Проверка Accessibility требует конкретных вызовов соответствующих API; `virtualdisplay` сам по себе не означает захват экрана. Для obfuscator учтены границы слов, исключены некоторые слишком общие признаки упаковщика; обычные intent-схемы и SAX URI исключены из соответствующих эвристик.
- Построение графа вызовов ускорено локальным кэшированием целей виртуальных вызовов. Для отдельного DEX добавлена явная оговорка об отсутствующем манифесте и зависящих от него проверках.
- Добавлены регрессионные тесты. Сборка: `go build -trimpath -o analyzer ./pkg/cmd/analyzer`; тесты: `go test ./...` (Go 1.27.3).

Для K-9 новая версия не создала malware-findings, однако остались HIGH-оценка безопасности и критические совпадения. Например, обнаруженные после прогона неоднозначные `isRegistered`, `keygen` и endpoint аутентификации исправлены отдельно, но финальная оценка приложения после этих точечных правок не измерена. HIGH/CRITICAL у вредоносных образцов означает общий риск, а не обязательно классификацию malware; так, основной категорией Exodus и Xhelper может быть Security.

Для Fossify оценка выросла: исходный прогон остановился по таймауту до data-flow, а новый запустил data-flow и сообщил о двух потенциальных путях path traversal. Это не доказывает ни уязвимость, ни ложное срабатывание; потоки нужно проверить вручную. Из-за разных таймаутов и покрытия сравнение рисков не контролируемое.

При последовательном прогоне K-9 от события rule engine до построенного графа в предыдущей и новой версиях прошло около 162 и 1,3 секунды соответственно; размеры графа совпали. Это не изолированный бенчмарк, нагрузки на систему и прочие условия отличались. Анализ data-flow затем потреблял до нескольких гигабайт памяти.

## Ограничения и дальнейшая проверка

- Все результаты таблицы помечены `incomplete`: достигнуты лимиты покрытия/data-flow. По ним нельзя считать приложение чистым или измерить общую точность; три обычных приложения и семь названных вредоносными APK не являются репрезентативным набором.
- В `spy277.dex` malware-findings нет, хотя исходный каталог обозначает образец как spyware. Манифест недоступен, независимая атрибуция отсутствует; поддержка DEX и подтверждение вредоносности требуют дальнейшей работы.
- Распознавание библиотек не доказательство их безопасности; R8 и переименованные классы осложняют классификацию. Новые правила для Accessibility могут пропустить вызовы через подклассы. Ослабленные общие сетевые правила могут привести к пропускам: необходимо измерить recall на отдельном размеченном корпусе и добавить проверяемые поведенческие цепочки.
- Остаются ложные HIGH-сигналы и проблемы производительности: лимиты data-flow, расход памяти и большие JSON-отчёты. Требуется расширить набор доброкачественных и вредоносных приложений, сравнивать одинаковые профили и настройки, рассматривать предупреждения вместе с контекстом, проверять каждый срабатывающий детектор.
- Изменение сопоставления по умолчанию может сломать пользовательские правила, рассчитанные на произвольную подстроку. Для каждого такого условия укажите `"match_mode": "substring"` и перепроверьте его; `"match_mode": "token"` явно выбирает новый режим. Не совмещайте `match_mode` с `exact`. Сохраните прежнюю версию и не используйте эту сборку как единственное средство защиты.
