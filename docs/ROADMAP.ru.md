## 1. Песочница: уровень ANY.RUN, локально и офлайн

Цель — опыт поведенческого анализа на уровне ANY.RUN, но работающий полностью на твоём железе, без регистрации, загрузки и облака.

**Что это значит на практике:**

- Полная поведенческая лента: каждый запуск процесса, запись файла, изменение реестра, сетевое соединение и вызов API в реальном времени в браузерном UI
- Богатая Android-детонация: SSL unpinning применяется автоматически до запуска, Frida-скрипты инжектируются на старте, весь трафик захватывается и расшифровывается без ручной настройки
- Улучшения Windows-детонации: трейсинг syscall на уровне ядра через eBPF/ETW, дампы памяти при подозрительном поведении, автоматическое извлечение строк из распакованных регионов
- Коррелированный вердикт: статические и динамические находки объединяются в единую ленту риска — видно "этот путь кода выполнился, этот сетевой вызов сработал, этот файл был создан"
- Пресеты окружения: чистый снапшот, рутованное устройство, эмулятор с Play Services, кастомный AVD — выбирается в пикере UI

## 2. ML: не просто "найти приватный ключ"

Большинство инструментов с ML либо используют regex под видом модели, либо гоняют облачный LLM. Здесь план другой — маленький, быстрый, локальный и реально полезный:

- **Умнее детект секретов**: не просто энтропия + regex, а контекстная модель, которая понимает, действительно ли строка используется как креденшл (передаётся в auth-функцию, отправляется по сети) или просто лежит в файле констант
- **Цепочки уязвимостей**: ML-пайплайн должен связывать связанные находки в цепочки атак — не просто "SQL-инъекция тут", а "пользовательский ввод идёт через X, достигает Y без санитизации, попадает в БД через Z"
- **Поведенческая классификация**: обучить GNN на динамических трейсах, а не только статических CFG — чтобы модель распознавала паттерны малвари по рантайм-поведению
- **Инкрементальное обучение на твоих прогонах**: каждый раз когда ты помечаешь находку как шум или подтверждаешь — локальная модель улучшается под твою кодовую базу, ничего никуда не отправляя
- **Уверенность, которая что-то значит**: Platt calibration + конформное прогнозирование — когда модель говорит 90% уверенности, она реально права в 90% случаев

## 3. Детект: больше сигнала, меньше шума

Цель — находить реальные уязвимости, в том числе закопанные в SDK, не топя отчёт в библиотечном boilerplate.

**Больше сигнала:**

- Глубже taint-трекинг через JNI-границу (Java → native → Java) для injection-цепочек, пересекающих языковую границу
- Поверхность атаки WebView: каждый `loadUrl`, `evaluateJavascript`, `addJavascriptInterface` отслеживается до источника для поиска XSS и путей утечки данных
- Расширенное покрытие десериализации: Kryo, Hessian, FST, Avro — не только стандартная Java-сериализация
- Supply-chain риск: флажок, когда зависимость имеет известный CVE *и* уязвимый путь кода реально достижим из приложения

**Меньше шума, но не слепота к SDK:**

Код сторонних SDK не пропускается — он анализируется. Разница в том, как представляются находки: чистый boilerplate получает низкий приоритет, но реальные риски в SDK (слабая крипта, захардкоженные креды, выполнение команд, небезопасный WebView) остаются с полным severity. Правило: **ни одна находка никогда не выбрасывается молча**.

## Что никогда не будет в роадмапе

- Облачная обработка любого рода
- Требование GPU или больших весов моделей
- Автоматический патчинг без явного подтверждения пользователя
