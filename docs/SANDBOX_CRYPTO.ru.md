# Извлечение ключей из анализируемого образца

Песочница сохраняет материал ключей, который образец передаёт поддерживаемым
криптографическим API. Результат находится во вкладке **Crypto keys**, в поле
`crypto_analysis` JSON-отчёта и в разделе **Captured Crypto Material** Markdown-отчёта.

## Запуск

- **Windows-VM, отчёты на своём ПК:** используйте `-sandbox-remote-config`.
  [Настройка VMware/Hyper-V и сохранения на хосте](SANDBOX_VM_HOST.ru.md).
  Отдельный сервер не нужен; штатные API-хуки включаются автоматически.
- **Android:** включите Frida. Режим spawn позволяет наблюдать инициализацию приложения;
  при attach ключи, созданные до подключения, могут быть пропущены.

Используйте изолированную аналитическую VM или Android-эмулятор. Нативный запуск
на текущем хосте по умолчанию заблокирован и не является границей гипервизора.
В удалённом режиме уже полученные ключи сохраняются на основной Windows,
даже если гостевая Windows перестала работать.

## Что извлекается

| Платформа | Источник | Материал |
| --- | --- | --- |
| Windows CNG | `BCryptGenerateSymmetricKey` | Переданные байты симметричного ключа после успешного создания |
| Windows CNG | `BCryptImportKey` | Ключ из корректного `KeyDataBlob`, после успешного импорта |
| Windows CNG | `BCryptEncrypt` / `BCryptDecrypt` | Связь с ранее захваченным ключом в том же процессе, IV до изменения буфера API |
| Android | Оба конструктора `SecretKeySpec` | Полный ключ или указанный диапазон байтов после успешного создания |
| Android | Перегрузки `Cipher.init` с `java.security.Key` | Экспортируемый ключ, transformation, режим и фактический IV после успешной инициализации |

Для каждой записи сохраняются источник, функция, PID, время, алгоритм, режим,
ключ и IV в hex, число одинаковых наблюдений. Дескриптор Windows не считается
ключом; ключи разных процессов не связываются. Уничтожение или замена дескриптора
прекращает его прежнюю связь. Запрос размера выходного буфера не считается
шифрованием. Алгоритм CNG определяется по наблюдаемому открытию провайдера;
если оно пропущено, алгоритм обозначается как `unknown`.

## Ограничения результата

`captured` означает, что материал наблюдался в API, а не что файл уже расшифрован.
`no_material` означает отсутствие захваченного материала; `not_instrumented` —
отсутствие активного перехвата. Эти состояния не являются вердиктом о безопасности образца.

Собственная криптография, аппаратные и неэкспортируемые ключи, opaque blobs,
CryptoAPI `CryptGenKey`/`CryptDeriveKey` и вызовы до установки хуков здесь не
восстанавливаются. CNG GCM/CCM хранит nonce/tag в отдельной структуре: текущий
перехват IV не извлекает эти параметры и не обещает готовую расшифровку.

Захват ограничен 256 уникальными записями, 256 байтами ключа и 32 байтами IV.
Превышение лимита записей или ошибка чтения журнала помечает результат как
`truncated`. Некорректный материал учитывается в `rejected`. Отчёты и журнал
Frida содержат сами ключи; храните их вместе с закрытыми артефактами исследования.

## Проверка без вредоносных файлов

```powershell
go test ./pkg/internal/sandbox -run 'TestCrypto|TestFridaSummary'
node scripts/test-sandbox-crypto.cjs
```

Тесты используют искусственные API-события, имитации Frida и тестовые ключи.
Они не запускают вредоносные образцы.
