# Запись TCP MITM по соединениям

Режим `-intercept` пересылает TCP-трафик на выбранный upstream и записывает
перехваченные данные. Для локального сервера на порту 9000:

```powershell
.\analyzer.exe -intercept -port 9339 -upstream 127.0.0.1:9000 -record capture.jsonl -net-flows
```

Несколько клиентов получают разные идентификаторы соединений. `-net-flows`
использует реальные адреса и исходные порты клиентов: запросы и ответы одного
соединения объединяются, трафик параллельных клиентов разделяется.

## Формат захвата

В каждой JSONL-записи сохраняются прежние поля `ts`, `direction`, `message_type`,
`size`, `data_b64` и добавляются:

| Поле | Значение |
| --- | --- |
| `connection_id` | Идентификатор одного TCP-соединения; содержит случайный префикс запуска, поэтому повторное добавление в тот же файл не смешивает сеансы. |
| `client_addr` | Фактический адрес клиента с исходным портом. |
| `server_addr` | Фактический адрес upstream после подключения. |
| `payload_offset` | Длина заголовка кадра при `-frame`; для сырых TCP-фрагментов поле отсутствует. |

Чтобы восстановить поток, отберите записи по `connection_id` и `direction`,
декодируйте `data_b64` и соедините байты в порядке записей файла. Без `-frame`
границы записей соответствуют чтениям TCP и могут отличаться от границ сообщений.
Старые захваты без идентификаторов не позволяют надёжно разделить клиентов.

Посмотреть соединения в PowerShell:

```powershell
$capture = Get-Content -LiteralPath .\capture.jsonl | ConvertFrom-Json
$capture | Group-Object connection_id | Select-Object Name, Count
$capture | Select-Object connection_id, client_addr, server_addr -Unique
```

`-net-json-events` добавляет те же сведения в поток событий: `connectionId`,
`clientAddr`, `serverAddr`. Для кадров `payloadOff` передаётся корректно,
поэтому JSON после бинарного заголовка доступен в `decoded`.

Запись сохраняет исходные перехваченные байты до интерактивного изменения
буфера. При включённом `ProxyConfig.RedactAuthorization` маскирование HTTP
заголовков ведётся отдельно для каждого соединения и направления, включая
случай, когда очередь записи переполнена. `size` описывает исходный размер;
после маскирования длина `data_b64` может отличаться.

## Остановка и полнота записи

В CLI остановите прокси через `Ctrl+C`. Веб-интерфейс использует управляющий
stdin: кнопка Stop закрывает канал, прокси завершает соединения, опустошает
очередь записи и закрывает файл. Если процесс не завершится за пять секунд,
интерфейс принудительно остановит его; сохранность буферов в этом случае
не гарантируется.

Флаг `-intercept-stop-on-eof` предназначен для такого управляемого запуска.
Его нельзя сочетать с режимами редактирования, использующими stdin.

После штатной остановки выводятся число пакетов, число соединений, потерянные
записи и ошибки записи. При переполнении очереди или ошибках диска CLI сообщает
`capture incomplete` и завершает запуск с ошибкой.

Эта функция работает с TCP-захватом. Расшифровка HTTPS зависит от отдельного
TLS-перехватчика и настройки доверия сертификату; сами поля соединения
расшифровку не выполняют.
