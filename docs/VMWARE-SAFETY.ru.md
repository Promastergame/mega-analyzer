# VMware: анализ в гостевой Windows

Веб-интерфейс запускает выбранный Windows-файл в обнаруженной VMware-ВМ.
Анализатор на основном ПК управляет VMware Tools, получает события и сохраняет
отчёт. Файл и сборщик исполняются внутри гостя. Ошибки VMware не переключают
исполнение на основной ПК.

## Запуск

1. Выберите EXE, COM, BAT, CMD или PS1 в «Динамическом анализе» и Windows-ВМ
   из библиотеки VMware. На хосте нужны Windows-сборка анализатора и `vmrun`.
2. Штатно выключите гостевую Windows. Приостановка не заменяет выключение.
3. Нажмите «Подготовить выключенную ВМ». Подготовка отключает виртуальные
   сетевые адаптеры, общие папки, буфер обмена, drag-and-drop и USB.
   Исходный VMX сохраняется рядом как `.mega-backup-…`. Ядра и RAM ВМ не меняются.
4. Укажите имя и непустой пароль одной учётной записи гостевой Windows.
   PIN-код Windows не подходит. Если при настройке тестовой учётки создан
   `guest-login.json`, нажмите «Загрузить логин и пароль из файла…» и выберите его.
   Оба поля заполнятся вместе; данные не сохраняются в браузере. Для следующего
   запуска пароль нужно ввести или загрузить снова.
5. В госте нужны VMware Tools. Сборщик запускается в фоне, поэтому открывать
   рабочий стол выбранной учётной записи вручную не требуется. Подтвердите
   запуск выбранного файла и нажмите «Start analysis».

Если подготовленная ВМ уже включена, анализатор проверяет гостевой вход,
штатно выключает её и повторно проверяет настройки перед включением.
Если выключение не подтверждено за 90 секунд, запуск отменяется.
Приостановленная ВМ по-прежнему требует ручного завершения работы.

Анализатор включает ВМ, ожидает Tools и проверяет гостевой вход до передачи
образца. В отдельный каталог `C:\Windows\Temp\mega-session-…` копируются
сборщик и задание, а файл — в подкаталог `input` с исходным именем.
Имя проверяется: пути, зарезервированные имена Windows и недопустимые символы
не принимаются. Перед исполнением проверяются SHA-256 файла,
оборудование VMware и отсутствие включённых сетевых интерфейсов гостя.

RAM ограничивается через Windows Job Object внутри гостя. Привязка к ядрам
применяется к процессу; её сбой отражается в предупреждениях отчёта.
Настройки основной Windows не меняются. Таймер начинается при запуске образца.
«До остановки» продолжает наблюдение до кнопки «Стоп», даже если корневой
процесс завершился или упал. Дочерние процессы отслеживаются по принадлежности
к Job Object. При включённом таймере выход образца также не сокращает сеанс.

## Остановка и результаты

«Стоп» передаёт команду гостевому сборщику. После наблюдения анализатор получает
отчёт и штатно выключает запущенную им ВМ. При потере связи гостевой сборщик
останавливает наблюдение через 60 секунд без нового подтверждения от хоста;
закрытие Job Object завершает его процессы. Неподтверждённое выключение ВМ
отмечается как незавершённый сеанс.

В выбранном воркспейсе основного ПК сохраняются `sandbox/vmware-…/`:

- `sandbox_report.json` и `sandbox_report.md`;
- `events.jsonl` с уже полученными событиями;
- `activity.jsonl`, записываемый на хосте по мере получения событий;
- доступные итоговые `stdout.log`, `stderr.log` и `activity.jsonl` из гостя.

Промежуточный отчёт обновляется после получения событий. При внезапном
выключении гостя или потере связи процессы, соединения и журнал, уже полученные
хостом, остаются в отчёте. Сеанс помечается как неполный без вердикта о
безопасности; сообщение о таймере появляется только при его фактическом истечении.
События, не успевшие передаться из гостя, таким способом восстановить нельзя.

Гость не выбирает пути записи на основном ПК. Забираются известные файлы
отчёта; созданные образцом программы автоматически не извлекаются.
Полученный журнал сохраняется при ошибке гостя. События ограничены 8 МиБ,
итоговый JSON — 16 МиБ; превышение отражается как ошибка или неполное покрытие.
Учётные данные не сохраняются в отчётах и заданиях гостя. Для гостевых операций
`vmrun` получает их как аргументы локального процесса.

Доступны базовые наблюдения процессов, сокетов, рабочего каталога и ключей
автозапуска. Вкладка Screen подключает живую консоль VMware через noVNC:
передаются обновления изображения, движения и кнопки мыши, прокрутка и клавиши.
Нажатие на экран передаёт ему фокус клавиатуры; кнопка Ctrl+Alt+Del отправляет
сочетание гостю. Переход в Output отключает управление. После остановки
остаётся последний кадр. Одновременно допускается один клиент консоли.

Перед включением ВМ анализатор временно настраивает VNC на 127.0.0.1 со
случайным портом и отдельным паролем для каждой сессии. Порт не открывается
в локальную сеть; браузер подключается через защищённый маршрут текущего задания.
Это соединение основного ПК с консолью VMware, оно не включает сетевой адаптер
гостя. Исходный VMX сохраняется в `.mega-console-backup-…`; после штатного
выключения прежние параметры VNC восстанавливаются без отката других настроек.
При аварийном завершении анализатора параметры могут остаться в VMX до
следующего запуска; локальная привязка и пароль сохраняются.

Буфер обмена между браузером и гостем не подключён. В поле «Где открыть
приложение» доступны фоновая сессия и рабочий стол гостевой Windows (по умолчанию).
Во втором режиме сборщик запускается с `vmrun runProgramInGuest -interactive`.
После включения ВМ пользователь должен войти на рабочий стол гостевой Windows
под той же учётной записью, что указана в панели. ВМ перед анализом
перезапускается; предварительный вход до этого перезапуска не сохраняется.
Анализатор ожидает входа до 90 секунд (в пределах общего трёхминутного
тайм-аута подготовки). Готовность проверяется фиксированной безвредной командой
`cmd.exe /c exit 0` внутри интерактивной гостевой сессии; образец не используется
для проверки. Сам сборщик запускается только один раз после успешной проверки.
Если вход не выполнен, запуск отменяется. Автоматического входа нет.
При ошибке нет автоматического перехода к фоновому запуску или исполнению на
основном ПК. Режим запрашивает интерактивную сессию, но не гарантирует, что
любая программа создаст окно. Фоновый режим не требует открытого рабочего стола.

Frida и PCAP в VMware-панели пока не подключены. Для Windows-криптоперехватов
есть [CLI-сборщик](SANDBOX_VM_HOST.ru.md).

## Снимки и границы проверки

Снимки создаются и восстанавливаются только при выключенной ВМ. Создание
требует подтверждения, восстановление — точного имени снимка: изменения после
него будут потеряны. Автоматического отката после сеанса нет.

Панель восстанавливает снимки `mega-baseline-…`, созданные этим инструментом
при выключенной ВМ. Подтверждения находятся в каталоге конфигурации пользователя
`mega-analyzer/vmware-baselines` и привязаны к каноническому VMX. Потеря
подтверждения отключает восстановление через панель, но не удаляет снимок.

Проверяются VMX, дескрипторы VMDK и цепочки родителей. Физические диски,
сетевые пути и неподдерживаемые дескрипторы блокируют исполнение.
Проверка настроек и снимок не гарантируют изоляцию или чистоту системы.
Не управляйте той же ВМ одновременно через другой клиент VMware.

## Проверки

Обычные тесты `go test ./pkg/internal/vmware ./pkg/internal/sandbox ./pkg/cmd/analyzer/web`
используют имитацию `vmrun`. `TestVMwareLocalSmoke` запускается только при явно
заданном `MEGA_VMWARE_TEST_VMX` и остальных переменных, перечисленных в тесте.
Он подготавливает, включает и выключает указанную ВМ. Для него нужен только
заведомо безвредный тестовый файл.
